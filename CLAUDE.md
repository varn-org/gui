# Varn GUI — project guide for Claude

Varn GUI is one Lua program describing an interface that three renderers draw with the widgets their platform already ships. The engine underneath is [varn-org/varn](https://github.com/varn-org/varn), which this repository consumes as a released binary and never builds. The higher-level Lua libraries that are not about interfaces live in [varn-org/components](https://github.com/varn-org/components).

This file is binding. Follow it exactly instead of re-deriving conventions each session.

## Core principles (non-negotiable)

- **No gambiarras, no fallbacks, no dead code, no legacy.** Write it the way an experienced product engineer at a top company would, using current best practices.
- **Nothing is kept for compatibility with how it used to be.** There is one version, the current one. A check that exists because something was different before is deleted along with the thing it was checking for. Take out, redo or refactor whatever needs it, without worrying about what depended on the old shape.
- **No `else` for unknown cases that create surprising implicit behaviour.** Handle the known cases explicitly. Do not paper over the unknown.
- **Comments are rare.** A name that says what a thing is leaves nothing for a comment to add, so most code carries none. Write one only where the reason is genuinely not visible in the code. Never write one to narrate a change that was asked for.
- **Code, comments and documentation are in English.**
- **No `;` splitting clauses, in code or in prose.** Two independent clauses are two sentences.
- **Do the work only when it genuinely makes sense and is actually needed — never just to show work.** An optimisation that measures at nothing is taken out again, not kept because it took effort.

## How the work is done

- **A round starts with a list, and the list is detailed.** `docs/review.md` is that list. An entry says what is wrong, what proves it, and what closes it — a one-line title is not an entry, because the next session will not remember what it meant. An entry closes only when it is built, tested and documented, and the box moves in the same change.
- **Everything the round establishes lands here.** This file is what the next session reads instead of re-deriving the same conventions, so a decision that is not written here did not happen.
- **Measure before building.** A rotation was assumed to hand the engine a size per frame and hands it four. A benchmark was written for a scenario that never happens. Three optimisations were tried against a slow layout and two of them did nothing. Take the measurement first and let it choose the work.
- **Say what is not done.** An item that is open is open, with its number and its cause. Do not describe an attempt that was withdrawn as if it shipped.
- **The user runs git unless they ask otherwise.** When they ask for a commit, it is one commit, amended rather than stacked, and the working tree is left clean.

## Commands

Everything goes through `python3 run.py <task>`:

- `test` — fetch a released engine into `.varn/` and run the Lua suite against it.
- `pack <dir> <out.vap>` — build an application archive from a project directory.
- `doctor <archive>` — validate an archive and report what is missing or unused.
- `sample` — pack the sample application into `sample/dist/`.
- `fetch-native` — download the released `varn.xcframework` and `varn.aar` the two mobile sample hosts link against.
- `shots` — build, install and screenshot every gallery screen on the iOS simulator, in both appearances.

The other renderers run the same suite themselves: `node --test renderers/web/tests` for the web, `xcodebuild test` in `renderers/ios/tests` for iOS, and `./gradlew :app:testDebugUnitTest` in `apps/android` for Android.

## Architecture and organization

- **The renderer owns no policy.** If a renderer has to decide something, the decision belonged in Lua and three renderers will disagree about it. This is the rule the whole project rests on.
- **Layout is computed in Lua** and renderers receive finished frames, each relative to the node it sits inside, since a renderer adds a child to its parent and the parent's origin is already applied. Text measurement is the one thing that crosses back, because only the platform knows its own font engine.
- **A commit sends one batch of operations**, never a call per widget and never the whole tree. Lua holds the virtual tree, the renderer holds the retained one, and neither reads the other's.
- **The host drives the runtime with `load` plus `poll`** on the thread that owns the interface, so every `host.*` call lands there and a renderer touches its views with no dispatch and no lock.
- **Lua owns the window and the reuse pools, the renderer owns the scroll view.** A list realises its own cells as ordinary nodes, and a pooled cell keeps its identity in the element tree, so reuse is the reconciler patching a subtree rather than a second mechanism beside it. The renderer contributes a native scroll view with a `contentExtent`, reporting its offset. It keeps no window and no pool.
- **A style is resolved into concrete values before it crosses the bridge.** Resolution happens in `Runtime:resolveStyles`, never in the diff, so no renderer carries a theme and three of them cannot disagree about what a spacing step means. A new theme re-sends every node its style.
- **Nothing crosses the bridge that json cannot carry.** `gui/bridge/wire.lua` turns a handler into the marker `true` and the removed sentinel into `"__varn_removed__"`, and refuses a cycle. A function never travels — the renderer reports an event by the name of the prop that declared it and the runtime finds the function again on this side.
- **The safe area and the keyboard are layout inputs.** The runtime holds them and `SafeArea` and `KeyboardAvoiding` turn them into padding, so a screen avoids the notch and the keyboard with no platform check anywhere in the tree.
- **Layout per module**: `gui/<area>/` holds the framework, `gui/components/<name>.lua` a component, `renderers/<platform>/` a renderer, `apps/<platform>/` the sample host, `docs/` the reference.
- **An event's payload is what the event carries, and nothing wrapping it.** A value-changing event carries the value itself (`onChange(true)`, `onChange("typed")`), a scroll carries `{ x, y }`, a selection carries `{ item, index }`, and a press carries nothing. A renderer that wraps a value in a table is broken, and the conformance suite says so on all three.
- **Light and dark come from the platform.** The host reports the appearance with the surface and again when it changes, `Runtime:setAppearance` follows it, and an application that passed a theme of its own keeps it. An application never carries a switch of its own for something the reader already set on their device.
- **The chrome is the platform's own proportions.** A bar is 44 high, a list row 60, a section header 34, and the type scale is the theme's — a value chosen per screen is how a screen ends up looking like nothing else on the device.
- **Binding invariants:**
  - A diff never emits an operation for an unchanged subtree. A re-render that changes one leaf produces one update.
  - **Every prop written as a literal is compared by value, not just the style.** A style was, and the four props carrying a list of their own were not: an icon's `commands`, a rich text's `spans`, a picker's `options` and a segmented control's `segments` are each built afresh by the render that names them, so each was an update over the bridge on every commit for a node that had not changed. An index of twenty rows with a chevron each is twenty of those. They are all in `LITERAL`.
  - **A style is compared by value and kept by identity.** A style is written inline at the point of use and is a fresh table on every render, so comparing it by identity marks the whole tree as changed: an update per node over the bridge and a layout that can keep nothing. `gui/diff.lua` names those props in `LITERAL` and `carried` hands the previous table forward when the new one says the same thing.
  - **A handler is not a change a renderer can see.** It travels as a marker, so a fresh closure over the same event is the prop the renderer already holds. The tree still takes the new closure, since that is the one that reads the state the render was made from.
  - **A box keeps its layout across commits.** Sizing a container asks each child for its size, hands it a share and asks again, so a subtree is visited several times per level and a tree that is worked out afresh costs three to its depth. `gui/layout/flex.lua` keeps what a pass produced, answers a repeat of the same question from it, and rebuilds a box only when the layout node's revision moves. A rebuilt box invalidates the boxes above it, since they can no longer stand on a size that is gone.
  - **A layout node is compared on what the engine reads**, never on the props table it came from, and a resolved style with nothing in it is one shared table so a node with no style of its own never looks changed.
  - **A cell is handed over in the order its pool slot was claimed.** Every cell is placed by a frame of its own, so where it sits among its siblings is nothing a reader can see, and reading order would move every row on the screen each time the window slides by one. The order a batch asks for is worked out against what the renderer holds after the removals, since removing a child renumbers every child after it.
  - **What a control is worth is the platform's to answer.** A size written into the tree is a number that was true of one platform on one day, and the engine sends finished frames, so a control drawn larger than the frame it was given spills out of it. A type says its size is `natural.platform` and the runtime asks once, the same way and for the same reason it asks what a string measures.
  - **A box takes no touch of its own.** A screen is a tree of boxes, and one sitting inside something that can be pressed would take the finger meant for it and answer nothing. A box the touch stops at with nothing inside it wanting the point steps out of the way. A scrolling view always keeps its content inside itself: a view only receives a touch within its own bounds, so content drawn past the edge both overlaps what is above it and cannot be pressed.
  - **A press is answered the way the platform answers one**, on all three, since a control that does not react to a finger reads as one that is not listening.
  - **A component owns its look, and the theme owns the values.** A control with no look of its own draws as bare text on every platform, so each type declares the style it has in theme names and a declaration may compute it from the props a caller gave — which is what a button's variant, a divider's colour and a chip's selected state are. A renderer draws a plain widget the style paints, never one the platform has already decorated.
  - **A node is created with a style, even an empty one.** A renderer told nothing leaves its widget at the platform's own defaults, and a label drawn at a size the engine never measured is given a frame a few points short of its own text.
  - **An element in a prop is never mounted**, since only the array part of a spec becomes children. Anything that takes content — screens, sections, a panel, the cells of a table — is a Lua component that builds what it was given into the tree, never a host node handing data to three renderers that each have to know what to do with it.
  - **A screen names the file it wants and nothing else.** The runtime expands an asset name against the bundle, taking the density variant the surface is drawn at, and refuses a name the bundle does not carry. A source with a scheme is left alone for the platform to fetch.
  - **The props of one node arrive in no order**, since a batch carries them as a map. A prop that builds what a node holds is applied before one that chooses among it, or a control loses its selection on whichever batch happens to be ordered that way. A pair of props that decide one thing between them — the axis and the indicator of a scrolling surface — is held on the view and worked out again whenever either lands, never read from the other at the moment one arrives.
  - **A node is created before it is ever given a frame, so anything written against its own size waits for one.** An arrival is drawn on the frame rather than on the create: a view animated before it is placed has nothing to animate from, and a travel written as a share of the node resolves to nothing at all. That is one defect wearing two faces — a modal that appeared instantly and a panel that did not travel.
  - **A transform's travel takes a percentage as well as a number**, and a percentage is a share of the node's own size. It is the only way a panel says it leaves by its own edge without the tree guessing at a height the layout works out, and it is re-read whenever the node's size changes.
  - **A layout leaves more behind than a size, and what a box may answer from memory follows from that.** It also leaves `pass`, which says whether a frame has to be sent, and the state of every box below it. So a box that answers from memory has to be left where a real layout would have left it, or it has to be certain nobody reads what it skipped. Three memos were written before this was clear and all three were withdrawn.
  - **A leaf may answer any question it has answered before**, since it holds nothing below it. It keeps its last eight answers, and answering one still runs `record`, so `pass` is set exactly as a layout would have set it.
  - **A container may answer a question only for the pass that is asking how large it is.** Sizing a container asks every child its size, shares out what is left and lays each child out for the share it was given, so the asking never decides where anything below the child sits and the layout that follows is what puts the subtree in agreement. An answer given there restores the size and nothing else — it leaves `laid` and `pass` alone and cannot survive the layout that follows. Without it a subtree is walked twice per level and a tree costs what it holds raised to its own depth: 2,615 real layouts a commit against 773, and a scroll in a split view at 14.9 ms against 5.7.
  - **What a box remembers is thrown away by whatever throws away what it last worked out.** A box that changes is rebuilt with an empty memo, but a box **above** one that changed is not rebuilt, so `build` clears its answers where it already marks it as no longer laid out. Without that a row keeps the width of the label it used to hold.
  - **Write a layout memo against the property test, never against a benchmark.** `gui/tests/layout_test.lua` lays sixty random trees out at ten sizes that come back around and compares every frame with a copy that has never been laid out at all, some of those boxes scrolling, since a box that scrolls asks its children something no other box asks. All three withdrawn attempts made a scroll several times faster and put things in the wrong place, and this is what said so. A second one grows a leaf in a tree already laid out, which is the shape a screen has and which the first cannot see. A hand-written case for that defect passed against it, because the row it measured was stretched by its parent and answered the container's width rather than its own — random trees find what a case chosen by hand was already shaped around.
- **What is shown over a screen is two layers and two moves.** A ground covers the screen and has nowhere to travel to, so it fades where it is. A panel travels, and that travel is what a reader reads as the thing arriving. Animated as one node the ground goes with the panel, so dismissing a sheet dragged the darkness down and uncovered the screen from the top. Every presented component is a fading `Presence` holding a travelling one, and `Presence` honours the style it is given so the panel is the node that moves.
- **A test says when it has finished, and the runner reads it back.** `async.run` schedules a body and returns, so everything after an `await` runs once the chunk has ended — and a second `async.run` in one file is never resumed at all. Both were true here, in four files, and the suite reported them as passing. Each test file has **one** asynchronous body, its `ok` is the **last line inside** it, and `run.py test` fails a file that prints no `ok`, that has two bodies, or that prints its `ok` outside one.
- **An application is told where it may write, and writes nowhere else.** A path relative to the working directory lands wherever the process was started, which is writable on a desktop and is not on a phone — so a picked file written that way works everywhere except the device it was written for. `gui.storage` is given the project's own directory when the application is launched.
- **Nothing that judges the gallery keeps a list of its own.** The screens `run.py shots` captures are asked of the catalogue, or a demo added to it is never looked at — which is what happened to four of them.
- **A margin moves a pinned box off the edge it is pinned to**, which is how a box of a known size is centred on one.
- **A screen that has been left is drawn leaving.** A caller derives its screens from what it is showing, so the one that was on top is gone from the list by the time the stack renders again. The stack is the only thing that saw it, so it holds it for the length of the move — put back where it was, and told to go on the commit after, since a node born in the state it is leaving in has never been anywhere else and there is nothing to animate.
- **What is pinned to an edge is pinned by the surface, never by the tree.** A commit follows a finger rather than leading it, so a header placed from Lua at the last offset it was told about drifts across the rows it is meant to cover on every flick. The tree says which node and over which range — `pinned = { from, to }` in content coordinates — and each surface holds it at `clamp(offset, from, to - extent)` as it scrolls, which is the push-out the platform's own lists have. It also takes a sticky list off the per-pixel commit it used to need.
- **A control that answers `noIntrinsicMetric` has no opinion about that axis.** Asking such a control to fit answers the smallest it can be drawn at, which is not an opinion: taking it made every slider on iOS 37 points across, a thumb with no track beside it. Only a control that answers nothing on both axes is asked to fit.
- **Being built and being seen are two different things.** A stack keeps the screen under the one on top and a tab bar keeps every tab, so a component that only hears about mounting loads work for screens a reader never looks at and goes on running behind ones they have left. Nine moments are reported — `onWillMount`, `onMount`, `onWillAppear`, `onAppear`, `onUpdate`, `onWillDisappear`, `onDisappear`, `onWillUnmount`, `onUnmount` — where the `will` half runs against the tree as it stands and the other half is held until the batch has reached the platform. Visibility is not something a subtree can work out for itself, so whatever is showing it says so with `gui.Showing`.
- **A ref answers rather than raising when what it pointed at has gone.** A ref is held across time — a timer that scrolls a list, a handler that focuses a field once an answer lands — and by then the screen may have gone. That is life rather than a mistake: the ref is emptied when its node goes and a call through an empty one answers no. Calling an action a component does not have still raises.
- **A test that is not in CI is a test that rots.** Half the browser suite and the whole of the suite that drives the gallery with a finger were run only by hand, and those are the ones that find what a tree-based case cannot. Both run in `check.yml` now, and the reference page is held to the declarations it is generated from.
- **A screen that asks for a commit from inside one for ever is stopped and named.** A component changing its own state from `onUpdate` is answered with another commit, which calls `onUpdate` again: the loop never idles, the device runs at full tilt with nothing moving, and nothing is reported. Fifty in a row is a mistake rather than a screen settling. A screen that converges after a few rounds is left alone.
- **Every declared type is one all three renderers can build.** The browser refuses a type it has no element for, so a component wired into two of them draws on two platforms and throws on the third. The check is derived from what the browser names rather than from a list somebody keeps.
- **A control that can be pressed says something.** A reader using a screen reader hears a control with no name, or nothing at all where one is. What a control holds counts, and one drawn as a picture carries its own words.
- **A failure inside a call the engine made never escapes it.** What a host registers is called from the engine's own frame, so an exception that escapes takes the process with it. All three answer the engine and report the problem instead.
- **A handler is set, never added.** A prop that comes and goes rebinds, so a listener added each time leaves a control reporting each event once per binding. One listener for the life of the view, and what it calls is swapped.
- **A view tag is not a place to keep anything.** Android refuses any tag key that is not an application resource id and throws where it is given one, so a key made from a string hash is a crash whose likelihood is the top byte of that hash. What a view has to remember belongs in a class of its own.
- **A batch is checked for what it carries as well as for what it names.** A width that is a string and an id that is a table both reach three renderers as something each reads as nothing, so every field of every operation has a type as well as a name.
- **A host that stops takes the tree with it.** Stopping the loop alone leaves every screen mounted, every timer firing and everything a node opened still open, on an interface nobody is looking at. Each host tells the engine it is finished and the tree comes down.
- **A number json cannot carry never crosses the bridge.** NaN and infinity both encode as `null`, which a renderer reads as no number and lays the node out at nowhere: a screen that vanishes with nothing said. A frame is checked before it is sent, the node keeps the one it had, and the problem is reported. The same guard already stood in front of a measurement.
- **Rendering a screen proves nothing about using one.** Every demo is rendered *and driven* — every press and every change a reader can make, with what the platform sends as the payload — and a problem reported while one is being used fails the suite. A handler that throws is where a screen actually fails, and a case that only renders it sees none of that.
- **A host gives back everything it set up to watch.** An observer on the page and a listener on what the reader set their device to go on reporting into an engine that has stopped answering. One signal for all of them, aborted where the pump stops.
- **Nothing that lands after the tree is down is half done.** A picture that arrives, a timer that fires, an event a host sends: every entry point answers nothing once `stop` has run, rather than building a tree from a root that is not there and reporting a failure for each thing that was still on its way.
- **What a node opened is given back when the node goes, and by nothing else.** Detaching is not removal: a cell that scrolls out of a list detaches and comes back, so a player closed there is a sound that never plays again and a map whose fetchers were shut down never draws another tile. The renderer knows when a node has gone, so that is where the release happens, and detaching only stops what is ticking.
- **Anything answering from off the main thread checks that what it answers is still there.** A tile that arrives after the map was released, a permission a reader granted after the screen was left, a fix that came back late. Each of those reaches a view that is gone, and each is dropped rather than delivered.
- **The half of the lifecycle that runs inside the diff is guarded like the half after it.** A component whose `onWillAppear` throws would stop the whole tree being built rather than only itself, so each of those is run through a pcall and reported the way a callback after the commit already was.
- **One arrival at a time.** Everything inside a pushed screen is mounted in the same commit as the screen, so a child with an arrival of its own adds its travel to the screen's and the pair comes in diagonally. A node mounted inside something that is itself arriving is built where it belongs and moves with it. The batch that builds it leaves the arrival out, the retained props keep it, so the next comparison sends nothing.
- **A field is not written back to anything it said itself.** A tree answers a keystroke with the value it has just been told, and by the time that lands the reader has typed two more: "Are you there" arrives as "Are you r". Each field keeps what it has reported since it was last written to and ignores all of it, and anything it never said is a real change that clears the history.
- **`table.unpack` anywhere but last is cut to its first value.** A conversation drew one bubble and nothing after it. Build one list and unpack it at the end.
- **A tablet is not a large phone, and the difference is read from the breakpoint.** A bar is 50 tall on iOS at a regular width against 44 on a phone, a screen keeps 20 at its edges rather than 16, a run of text is capped at a width somebody can read, and what is shown over a screen is centred in a panel the width of a form sheet rather than covering the whole of one. All of it lives in `gui/style/chrome.lua` beside the bar heights, and nothing anywhere reads a device name to get it.
- **A box that does not clip its drawing does not clip its touches.** A view answers a touch only within its own bounds on both phones, so a child drawn past the edge of the box it belongs to is seen and never pressed — the raised picture on a tab bar is the case that found it. What is drawn outside is meant to be pressed, and a box that clips its drawing clips its touches with it.
- **Anything on screen may be told to let a finger through it.** `pointerEvents` is universal, like a key, a style and a label: a picture drawn over the control that chose it is not meant to take the press aimed at it, and a component that has to declare the prop first is a render that throws on the screen a reader is looking at.
- **A failure a reader can see is something they can put away.** The sample hosts drew a problem into the view as a label that stayed for the rest of the session, carried from screen to screen. A banner with a way to dismiss it, or the platform's own toast.
- **A control claims a finger that landed on its own drawing.** A plain view takes a touch on iOS whether or not it has any use for one, so an icon inside a tab swallowed every press aimed at it — the bar looked right and answered nothing, and landing beside the icon got through, which is a control pressed three times to be heard once. Anything inside that answers a finger of its own keeps it, and everything else hands the press to the control it is drawn in.
- **A press is given up to the gesture that beat it, never to a distance.** A finger on a phone is never still and a control inside a list moves under one that is, so a press held to a travel of its own is a control a reader presses three times to be heard once. The platform already arbitrates this: UIKit answers a press wherever the finger is lifted inside the control, Android gives one up when the touch leaves the view, and a swipe recogniser cancels the touches it recognised on. Only the node the tree asked a swipe about gives its press up to one, and a browser suppresses a press only for the node that was actually swiped, never for a click the keyboard raised.
- **A sound is silent until the application says playing is what it is for.** A phone on silent plays nothing through the default session, and most phones are on silent, so the session is set to playback the moment a sound or a video is given a source.
- **Written into a demo is not drawn by one.** A check that searched the demo sources for a component's name passed a player that was declared in a file the gallery loads and put into no screen at all. Every demo is rendered, every switch on it is turned on, and the node types that come out are what the check reads.
- **A scrolling surface hands a touch straight to what is inside it, and asks for it back.** A `UIScrollView` holds a touch to see whether it is a scroll, which delivers a press late and swallows a quick one, so `delaysContentTouches` is off and `canCancelContentTouches` is on, the way the platform's own lists have it. Android is the mirror image: a child that answers a press consumes the whole gesture, so a surface with no `onInterceptTouchEvent` does not scroll at all over its pressable rows, and it takes the finger once the drag passes the platform's scroll threshold.
- **A press with no finger behind it is still a press.** A click raised by the return key on the web carries no pointer, so nothing about the last gesture's travel applies to it — suppressing it is a control that cannot be reached with a keyboard at all.
- **A finger that travels is not a press, and every renderer has to say so.** A control on iOS fires when a drag ends inside it however far it went, a view on Android gives up a click only when the touch leaves its bounds, and a browser raises `click` for any pointer that goes down and comes up on one element. All three let a swipe across a row open it. Each is held to the distance its own platform allows a tap.
- **A press, a hold and a swipe are three things.** `Pressable` reports `onSwipe` with the direction the finger went, since an item does something different for one.
- **An interface that changes shape is one tree, not two.** Rendering a split where there is room for both and a stack where there is not means a turn of the phone crosses between two trees, and everything under either is taken down and built again — a reader loses what they typed for having held the device sideways. Both panes stay mounted, keeping their place and their keys, and only their layout changes. `SplitView` does that, and a stack at its first screen takes `onBack` so the collapsed detail column still has somewhere to go.
- **A stack keeps every screen it holds, and shows only the top one.** `NavigationStack` renders every screen up to the index, the top one in the flow and the rest exactly where they were, covered, undrawn and taking no touches. Rendering only the top unmounts everything under it, so coming back is a screen that has never been used: a list at the top, a field emptied, a form that forgot. Leaving the covered ones **drawn** is the other half of the same mistake: a screen is not required to paint a background, so the shop's grid read through the product page over it and the checkout over both. Held, not shown. It costs a covered screen per commit, which is 5.7 ms against 6.5 ms on a split-view scroll.
- **`x and y or z` is a Lua bug wherever `y` can be false or nil, and it reached the core.** `setState` was written `value ~= none and value or nil`, so **every state a screen set to false was stored as nothing at all** — it reads as false everywhere except against false itself, which is where it surfaced. The headless renderer had the same line for a prop arriving in an update, so every test asking whether a prop is false after one was weaker than it looked. Write the `if`.
- **A control the platform sized on an axis is not stretched along it.** A switch is fifty-one points across because that is what a switch is, and one stretched down a tablet is drawn in the corner of a box the width of the pane with every point of it answering a finger. A platform with no opinion about an axis answers nothing for it — a slider, a segmented control, a dropdown — and those fill the room they are given. The rule was written twice, once where a child is measured and once where it is placed, and only one copy knew: **one question, one answer, asked once.**
- **Which of a control the tree asked for is part of asking what it is worth.** A wheel date picker and a compact one are two different things to lay out, and `gui_measure_control` asked about the type alone — so the wheel took a height written into the tree and was stretched to whatever width was going, which on a tablet is 652 points of three date columns and a screen that scrolls badly for it. The call carries a variant, the answer is cached per variant, and a control the platform sized on both axes says so with `alignSelf` rather than being stretched.
- **A runtime can be taken down.** `Runtime:stop` unmounts the tree, which fires every `onUnmount` and so ends every timer a screen asked for. Without it a screen that repeats something holds the engine's loop open for the life of the process, and a test that mounts a demo and walks away leaves it running — which is what stopped the suite terminating.
- **A component built from the others is not a node three renderers have to know about.** A chip was a host type that every renderer drew as a text box, so a `removable` flag would have been three drawings of one glyph. It is a pressable pill holding its label and the mark that takes it away, and the `chip` type is gone from all three. The same reasoning made a skeleton lines rather than one flat box.
- **A key says two nodes of the same type are different things, wherever the node sits.** A component's own root is compared with nothing above it — there is no key lookup the way there is among siblings — so comparing on the type alone made it immune to its key and it was patched in place rather than replaced. Nothing about it was new, so `enter` was never applied: every overlay, drawer and pushed screen arrived in one frame while the way out of them animated correctly. `Presence` is built on exactly that change of key.
- **A frame writes only what the style names.** A node is framed again in the commit after the one that creates it, and a travel written as a share of the node has to be re-resolved when its size changes — but a node arriving carries its travel in `enter`, not in its style, so re-resolving from a style naming none reset it and the arrival had nowhere to come from.
- **A box told to take no finger takes none for anything inside it either**, on all three. Stopping the box alone leaves every control within it answering a press that should never have reached it, which is what a covered screen in a stack is made of. On Android that means refusing to dispatch, so the platform carries on to the next sibling rather than swallowing the touch.
- **Padding is declared in one place.** A control that draws its own text is inset by its **style**, which is what the renderer reads, so that is where its padding lives. `natural.padding` is for room a renderer needs for a part it draws itself — a checkbox's box — and a type that declares both has its padding counted twice: a badge of one digit came out 32 across for a pill that is 20.
- **What a type is never smaller than is a floor on the box, not on the text.** Applied to the text it is the padding over again. A badge's `minWidth = 20` means the pill is twenty across.
- **A gesture that leaves a screen is an edge gesture, and it acts when the finger lifts.** A swipe recogniser over the whole surface takes a drag on a checkbox, a slider or a carousel as a request to leave, and it fires the moment the movement passes its threshold, so the screen goes while the finger is still down. An edge pan, acted on at `.ended`, past a distance or a speed.
- **A screen says nothing about the system's own bars unless it means both appearances.** Every platform draws them from the appearance already, so a tree that names nothing follows light and dark for free. The sample named `light`, which read correctly in the dark and put white glyphs on the white bar the light appearance turned it into. `barContent` pins it, and belongs only on a screen whose bar keeps one colour either way.
- **A mark is drawn, never written as a character.** A glyph like `⌃` is a different shape and a different size in every platform's font, and inside a `numberOfLines = 1` text it is the first thing a long title truncates away. The engine ships an icon set for exactly this — a table's sort order, an accordion's state, a row's chevron.
- **A surface draws a bar only for the axis it scrolls**, and a paged one draws none at all, since it says where it is with its dots. One prop applied to both axes gave every vertical list a horizontal bar it has no use for.
- **What is inside a scrolling surface travels with what it scrolls.** A carousel's dots were children of the surface, so they were only ever seen over its first page. Anything that has to stay put is a sibling over it.
- **A view that reads a whole batch reads it once.** A centre, a zoom and a set of marks describe one region between them, so a map told each of them separately moves three times for one change, and a location node asked again for every prop asks the reader for a permission again. The renderer applies a batch and then settles the node — `VarnSettling` on iOS and Android, `settle()` on the web — and a frame settles it too, since how much of the world fits depends on how wide the map turned out to be.
- **A platform that reports a change does not always say who made it.** MapKit reports the region changing when a reader drags the map and when the map re-fits itself to a new size, and taking both as a reader's move means the tree is told its own props back and the map fights itself on every commit. The gestures are watched alongside the platform's own reporting, and only a reader's move is passed on.
- **A map is drawn in tiles, and only one platform gives you one.** The zoom is the one every raster map on the web is cut in, so a centre and a zoom mean the same thing on all three. Apple gives MapKit away, and Android's own map is Google's — a dependency, a key and an account before a screen can show a street — so the Android renderer and the browser draw the tiles themselves and credit OpenStreetMap on the map, which is what its licence asks. MapKit thinks in degrees rather than in tiles, and a degree of longitude covers less ground the further from the equator it is, so a span worked out without that is widened rather than refused and the map sits at a zoom nobody asked for.
- **A capability the device grants is asked for by mounting the thing that needs it.** A `Location` is on screen for as long as a screen wants a fix and takes the receiver with it when it goes, so nothing runs behind a screen a reader has left. A refusal is reported through `onError` rather than left waiting, and on Android a permission belongs to the activity, so the renderer asks the host for one the way a file chooser does.
- **Something a reader is given a piece at a time is reported a piece at a time.** `onPick` reports one file per call, since gathering a set of photographs puts the bytes of every one of them into a single message that is decoded and written in one turn of the loop, and nothing moves until the last one lands.
- **Measure the thing that happens.** A rotation was assumed to hand the engine a size per frame and does not — UIKit sets the final bounds at once and animates the presentation layer, four reports for a full turn. The freeze was in scrolling, which nobody had timed.
- **A performance claim is a measurement, not a hunch.** Three of the four things tried against a slow rotation did nothing, and one of them was slower. The profile named a line nobody had suspected. Measure, keep what moved the number, and write down what did not.
  - **A performance budget is a test, not a hope.** `gui/tests/performance_test.lua` fails when re-rendering the index sends anything at all, when a keystroke costs more than four operations, when a uniform list scrolling one row costs more than twelve, when a scroll reorders a cell that did not move, or when a tree twenty-four deep measures its one string more than a handful of times.
  - A keyed child survives a reorder with its state. Identity comes from the key when there is one and from position when there is not.
  - `setState` schedules a commit and never runs one. Ten calls in a handler produce one diff.
  - A `setState` from inside `render` is an error, not a second commit.
  - The measurement cache is keyed by every input it depends on, and is dropped when a font is registered or the scale changes.
  - A list reuse pool is per item type. A cell of one type is never handed to another.
  - An archive is expanded once into a cache keyed by the hash of its bytes. A partially written cache is discarded rather than trusted.
  - A renderer declares its capabilities at start, and `renderer:can(name)` is how a caller reads one before asking for it. There is no helper that refuses on a caller's behalf: one existed, nothing ever called it, and its only test exercised itself.
  - **An index in a placement counts the siblings the node is not among.** A renderer detaches the node before it reads the index, or a move to a later position silently does nothing. The conformance suite catches this, and it caught it once already.
  - A component declaring a prop it does not accept is impossible: `docs/components.md` is generated from the declarations themselves by `gui/tools/reference.lua`.
  - Every component the library exposes appears in the sample application, which `gui/tests/sample_test.lua` enforces by name.
  - **A `nil` in the array part of a table cuts the list short at that point.** A conditional child is appended to a list rather than written in place, and a state field is cleared with `gui.none` rather than `nil`, which `setState` would never see.
  - A control with a size of its own does not shrink. A switch is the size the platform draws one at, and squeezing it to make room for a long label leaves something nobody can recognise or hit.
  - A handler runs after the commit, never during one — a list queues what appeared and disappeared and flushes it in `onUpdate`, since a handler is free to call `setState` and a commit may not start inside a commit.
  - `onLayout` is answered by the engine's own layout rather than by a renderer, so a renderer ignores that prop.
  - **Every colour is resolved to `#rrggbbaa` before it crosses the bridge.** A renderer reads a colour rather than parsing one, so a theme name, an `rgb` call and a three digit hex all arrive in the one shape. Three parsers meant three chances to disagree, and two of them read nothing that did not start with a hash: the theme's `overlay` is an `rgba` call, so the scrim behind every overlay was invisible on both phones and an alert read as the page it was covering. A colour carried as a prop — a switch's tint, a slider's track — is resolved the same way as one in a style.
  - **A change a reader is meant to follow takes time.** A node carries a `transition` and every later style change is drawn over it. Only opacity and the transform animate, so the frames the layout worked out are never disturbed. An easing is defined once as four cubic-bezier control points and sent as those four numbers, which is exactly what `cubic-bezier`, `UIViewPropertyAnimator` and `PathInterpolator` each take, so no renderer ever interprets a name.
  - **Something leaving is held until it has left.** A node removed from the tree is gone the moment the commit lands, so an overlay dismissed by a handler would vanish rather than animate away. `gui.Presence` keeps what it carries mounted for the length of its exit, hands the renderer the state to animate towards, and only then lets go.
  - **The chrome is the system's own, and it is the only thing that reads the platform.** `gui_surface` carries a `platform`, the runtime provides it above the whole tree, and `gui/style/chrome.lua` is the one file that reads it: a bar is 44 tall with a centred title and a chevron carrying the previous screen's name on iOS, and 56 with a leading title and a bare arrow on Android. Layout, styling and behaviour stay free of it, and a component reading it to pick a colour or a size is doing it wrong.
  - **A scroll view is asked to change nothing that has not changed.** `UIScrollView` lays out on every change of its offset and writing `contentSize` makes UIKit clamp the offset again, so re-assigning the same size fought the rubber band on every frame — a list that trembled wherever it was pulled past its last row.
  - **A scroll that puts nothing new on screen costs nothing.** A platform reports every pixel a finger moves and a commit lays out the whole tree, so a list returns early unless the realised range actually moved.
  - **A scrolling type owns its own overflow.** A style that names none may not clear it, or every list carrying a style stops scrolling — which is what happened to every list in the gallery on the web.
  - **The engine fetches a picture, not the renderer.** A phone hands an `https://` string to its image view and quietly draws nothing, so a remote source is fetched once with the engine's own http client into the archive's cache and every renderer is handed a local file. A renderer that shares no filesystem with the engine declares `imageBytes`, the way it already declares `fontBytes`, and is handed a data URI instead. Redirects are followed, since every picture service answers with one. The placeholder is what is drawn while a picture is on its way and what stays when it never comes, and the engine reports `onLoad` and `onError`, since the engine is what knows.
  - **The keyboard is something the tree is responsible for.** Done takes it away and `next` does not, a press outside what is being typed into takes it away, a drag on a surface that asked for it takes it away, and a focused field the keyboard would cover is scrolled clear of it from the frames the engine already has. The runtime remembers what has focus, which is why it knows what to reveal.
  - **A touch target is never smaller than the guidelines allow.** Forty-four points, counting a hit slop, on everything a finger lands on. `gui/tests/guidelines_test.lua` walks every screen of the gallery and fails naming what is too small, so this cannot rot.
  - **A declaration is a promise, and a test keeps it.** `support.host` says its props are the ones a renderer honours and `docs/components.md` is generated from them, so a prop listed there is one a caller writes and believes. `gui/tools/promises.lua` reads every declaration and searches the three renderers and the components for the prop by name, and `gui/tests/promises_test.lua` fails when nothing anywhere reads one. A sweep found two hundred and fifty-four. A prop that exists only in the documentation is worse than one that does not exist, so a new one is either honoured somewhere or it is not declared.
  - **A commit that fails does not take the application with it.** `Runtime:commit` runs the build under `pcall` and restores `committing` either way, then re-raises. A flag left set makes `needsCommit()` answer false forever, so one bad render, one refused batch or one missing asset would leave the application dead while still running.
  - **A failure reaches the host, not the log.** Opening a project runs on a coroutine, so a failure there would be reported where nobody is looking. `launch.start` takes an `onProblem`, every host registers `gui_problem`, and every sample app shows what it is told. A blank screen that says nothing is the defect this closes.
  - **What a handler does is not the runtime's to trust.** `Runtime:dispatch` runs a caller's handler under `pcall` and reports the failure through `onProblem`, since an error escaping into the host's event delivery takes the frame with it.
  - **An overlay is built rather than asked for.** `Modal`, `Sheet`, `Alert`, `ActionSheet`, `Menu`, `Toast`, `Accordion`, `TabBar`, `NavigationStack`, `Drawer`, `Table` and `RadioGroup` are Lua components that build a cover, a scrim and their content out of the host nodes that already exist, so they work on all three with nothing added to a renderer. A node type no renderer builds falls through to a plain box and puts nothing on screen, which is what "I press it and nothing happens" was.
  - **A control reports the number the tree declared, not the position the platform tracks.** A slider maps its range and its step onto whatever the native control counts in and maps back when it reports, so the same Lua slider answers the same values on all three. Reading the position back as the value is how a slider reported a hundredth of what it was dragged to.
  - **A platform with no control for a type builds one out of parts of its own.** The engine sends `segmented`, `rating`, `stepper` and `picker` no children, so what is inside one belongs to the renderer the way a `UISegmentedControl`'s segments belong to UIKit. A type that draws as an empty box is not a renderer that is behind, it is a control nobody can use.
  - **A commit never names a node it removed in the same batch.** The index the style pass and the picture repaint walk is rebuilt inside the build, before either of them runs, and a component the dirty set still holds is skipped when an ancestor has already rendered it away. Both were remotely reachable ways to produce a batch that updates ids it had just removed, which kills the process on Android, throws out of the wasm callback on the web, and on iOS leaves the screen permanently half drawn with nothing said, since the diff only ever sends what changed and nothing repairs it.
  - **The layout answers what moved, and the runtime keeps every frame.** A caller that reveals a field or scrolls to a row asks about a node the layout had no reason to touch, so keeping only what moved left the map empty after the first state change and keyboard reveal did nothing at all.
  - **A build that fails keeps what it had not reached.** The dirty set is taken one node at a time rather than cleared up front, so a render that throws does not silently drop every component behind it — their state has already changed, and they would render stale until something unrelated marked them dirty again.
  - **A `setState` while a commit runs is recorded, not dropped.** A component notified by another one's render changes its state during the build, and returning early without recording it left the node dirty with nothing coming for it.
  - **A component whose root child changes type is put back where it was.** The replacement is attached to the nearest host above it, at the position the branch it stands in occupies. Reading a `parent` and an `index` that nothing ever assigned meant the old node was removed, the new one created, and nothing inserted: the ordinary spinner-then-content shape went permanently blank.
  - **Nothing the engine does inside a commit waits.** A commit holds the tree, so an `await` in the middle of one either raises outside a coroutine or yields with the tree halfway between two states, and every `setState` in that window is lost. A picture's bytes are asked for during the commit and answered after it, the way a fetch already was.
  - **A picture that could not be had is asked for once.** The answer to a failure schedules the repaint that asks again, so an unreachable image was one request and one full-tree commit per round, forever, and an application opened offline never stopped.
  - **Anything keyed by what an application produces is bounded.** Text measurements are keyed on the text itself, so a clock adds an entry a second for the life of the process, and a data URI is larger than the picture it carries. `gui/tools/cache.lua` holds a bounded number and gives up the coldest. A node id only ever increases, so an extent is dropped when its node is.
  - **A component asks for something later through `self:after`.** It checks the delay is a number of milliseconds, does nothing if the component has gone, and reports a failure rather than letting it out: a body handed to `spawn` is caught by nothing above it, so the engine reports it unhandled and stops the loop for that tick.
  - **An instance keeps the scheduler it was born under.** The component layer is pointed at one per runtime, and two runtimes in one process would otherwise share the last to start, so a component would ask a runtime that does not hold it to draw it.
  - **`Runtime:report` never raises.** It is reached from the middle of a commit and from the callbacks a commit owes, so raising there is the very failure it exists to contain. With no listener it writes to the log.
  - **A prop is honoured by all three or it is not declared**, and the check that keeps it only counts a name where a renderer could be reading it: not in a table keyed by node type, not in the factory that chooses a view for one, not in the type a component names itself after, and a bare table key only for an event. Each of those was giving a prop a pass against a row that had nothing to do with it.
  - **A colour on a control is the colour of the mark it draws**, which is a different thing from a style's colour, and all three took the platform's accent instead until it was built.
  - **An action asked of a node that cannot answer it is refused, the same way on all three.** `scrollTo` on something that does not scroll and `play` on something that is not a video each raise a named refusal, rather than one throwing, one doing nothing and one doing something else entirely.
  - **A picker reports what a calendar or a clock shows, never an instant.** `"2026-09-05"` and `"09:30"`, in and out. An instant carries a zone nobody chose, and reading it back in another one moves the day.
  - **The engine owns the icon set.** `gui/style/icons.lua` carries them as runs of points and `Icon` draws them onto a `canvas`, which every renderer already draws. A platform that ships thousands of symbols ships them under names no other platform has, so a name that resolved to one of those could only ever have drawn on one platform out of three.
  - **A string is measured with what it will be drawn with.** The spacing between its letters, the space between its lines and the slant of them all change how much room it needs, and a measurement is named by every one of them, or the same string at a different spacing answers the previous measurement.
  - **The tree writing a value back is not a person choosing one.** A control set from a prop reports nothing, or a handler that stores what it was given comes round again as a second choice, and a platform that reports a programmatic change down two paths reports it twice. Each such control remembers what was written into it and reports only what was not.

- **`x and y or z` is a bug wherever `y` can be nil.** Lua takes the `or` branch when the middle value is nil, so a layout that read `row and child.width or child.height` used a child's height as its width, and one that read `row and child.height or child.width` centred a fixed column against its own width. Both were real and both were invisible to every test. Write the `if`.

## Lua style

- Match the existing visual, structural and architectural pattern. Compact, professional, consistent.
- Avoid excess vertical space. Use only the blank lines needed to separate reading contexts. **Separate blocks of different responsibility with one blank line.**
- Never leave multiple `if`s, validations, loops, state mutations and returns visually glued together. A function must read with an identifiable beginning, middle and end at a glance.
- Prefer early returns. Avoid unnecessary nesting. **No unnecessary `else` after a `return`.**
- Extract a function only when one is doing too much — never to shrink size or for artificial abstraction that hides the main flow.
- A module returns one table. Locals are declared at the top of the file, and a function that is not part of the module's surface is local.
- **No global writes.** Every module is `local M = {}` and `return M`.

## Comments

- **Most code has none.** The bar is that a reader who knows the language cannot work out the reason from the code in front of them.
- **Every comment is a complete sentence: it starts with a capital letter and ends with a full stop.**
- **A sentence never starts with a lowercase identifier.** Keep the identifier's exact spelling and reword the sentence so it is not the first word.
- **A comment above a function, method, class or module says what it does for the caller, never how it is implemented inside.**
- **Never break one sentence across lines, and never continue a sentence on the next line.** If you need a second sentence, close the first with a full stop and start the next on its own line.
- Comments are objective and natural. Nothing verbose, fragmented or narrative, no decorative banners, and no historical or before/after framing.
- A comment explains intent or context. It never restates what the code literally does, and usage examples belong in the docs.

- **A view is never placed by its frame on iOS.** `UIView.frame` is undefined while a view carries a transform, and the engine animates transforms while writing frames on every commit, so a commit landing inside an animation moved a view for good. Bounds and centre mean the same thing whatever the transform is — and only the size is written, since a scrolling view's `bounds.origin` is its content offset.

## Testing

- Every module has tests under `gui/tests/`, run by `python3 run.py test` against a released engine.
- **A renderer is proven by the conformance suite**, not by looking at a screen. All four run the same cases and apply operations identically, and `gui/tests/conformance_test.lua` refuses a suite that does not carry exactly the same case names.
- **A screen is proven by touching it.** `apps/ios/UITests` opens a demo from the index, types into a field, chooses a radio, counts a button, scrolls a list past the bar, opens a section, sorts a table and drives the request. Four of its twelve cases failed while every conformance case passed, because a tree-based case cannot see that a row will not answer a finger.
- **A screen is proven by looking at it.** A tree-based case cannot see a node that reached a renderer and was drawn as nothing, which is what an empty accordion, an invisible badge and a picture that never loaded each were. `python3 run.py shots` captures every screen in both appearances.
- The headless renderer records operations, so the framework is testable without a device.
- **A row that carries a name of its own is one element.** Its text is not exposed separately, so a UI case that asks for `staticTexts[...]` finds nothing and reads as a defect in the application. Ask for any element with that name.
- **A renderer's own defects are tested in the renderer's own language.** `renderers/ios/tests` runs under `xcodebuild`, `renderers/android/src/test` under Robolectric, `renderers/web/tests` under `node --test`. A defect that only exists inside `UILabel` or a `TouchDelegate` cannot be reached from Lua.
- **A whole application is a test too.** `sample/apps/` carries a shop, a podcast player and an account screen, each several screens with state, navigation and a keyboard, and `gui/tests/apps_test.lua` drives each one down its main path. A component that works alone and falls apart in an application is one nobody would ship.

## Proving it

- **Touch it.** `apps/ios/UITests` opens every overlay by pressing what opens it. A screenshot shows the state a screen opens in, and a modal, a sheet, an alert, an action sheet, a toast, a menu and a drawer are none of them in it.
- **Look at it.** Every defect in section G of `docs/review.md` passed every suite here and was found by a person holding the application. `python3 run.py shots` and a real device see a class of defect no tree-based case can.
- **A test against a stand-in proves the stand-in.** A fake canvas has no size to be wrong about, so a canvas sized from the element's own box passed every web test and would have drawn nothing in a browser. Where a test cannot see the platform's own behaviour, say so rather than counting it as covered.
- **A defect found on one platform is looked for on the other two before it is called closed.** The line count a frame overwrote, the radio that reported nothing, the surface that would not page: each was found on one renderer, fixed there, and left standing on another until a second read.
- **A fix is proven by a test that fails without it.** Write the test, revert the fix, watch it fail, put the fix back. Several of the worst findings of the last review were things a passing suite had been asserting the wrong way round, and three tests written this way each found a second defect the review had not seen.

## Docs

- **Prose in Markdown is never hard-wrapped.** One paragraph is one line, however long it runs, and a list item is one line with its continuation folded in.
- **A sentence starts with a capital letter.** The product is `Varn GUI` in prose. A sentence never opens with a lowercase identifier — reword it so the identifier is not first.
- `LICENSE.md` is never reformatted.
- Docs are two-tier. Tier one is the `README.md` next to the code. Tier two is the reference under `docs/`, which carries the complete API and a runnable example of every capability. `docs/components.md` is generated — regenerate it with `gui/tools/reference.lua` rather than editing its table by hand.
- `docs/review.md` is the one live list, and an item closes only when it is built, tested and documented. Closing one means moving its box in the same change. A finished round's checklist is deleted rather than kept: four of them were kept once, they contradicted each other and the source, and one was linked from the `README` as documentation.
