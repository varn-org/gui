# Varn GUI — project guide for Claude

Varn GUI is one Lua program describing an interface that three renderers draw with the widgets their platform already ships. The engine underneath is [varn-org/varn](https://github.com/varn-org/varn), which this repository consumes as a released binary and never builds. The higher-level Lua libraries that are not about interfaces live in [varn-org/components](https://github.com/varn-org/components).

This file is binding. Follow it exactly instead of re-deriving conventions each session.

## Core principles (non-negotiable)

- **No gambiarras, no fallbacks, no dead code, no legacy.** Write it the way an experienced product engineer at a top company would, using current best practices.
- **Nothing is kept for compatibility with how it used to be.** There is one version, the current one. A check that exists because something was different before is deleted along with the thing it was checking for. Take out, redo or refactor whatever needs it, without worrying about what depended on the old shape.
- **No `else` for unknown cases that create surprising implicit behaviour.** Handle the known cases explicitly. Do not paper over the unknown.
- **Comments are rare.** A name that says what a thing is leaves nothing for a comment to add, so most code carries none. Write one only where the reason is genuinely not visible in the code. Never write one to narrate a change that was asked for.
- **Code, comments and documentation are in English.**
- **No `;` splitting clauses, in code or in prose.** Two independent clauses are two sentences.
- **Do the work only when it genuinely makes sense and is actually needed — never just to show work.** An optimisation that measures at nothing is taken out again, not kept because it took effort.

## How the work is done

- **A round starts with a list, and the list is detailed.** `docs/review.md` is that list. An entry says what is wrong, what proves it, and what closes it — a one-line title is not an entry, because the next session will not remember what it meant. An entry closes only when it is built, tested and documented, and the box moves in the same change.
- **Everything the round establishes lands here.** This file is what the next session reads instead of re-deriving the same conventions, so a decision that is not written here did not happen.
- **Measure before building.** A rotation was assumed to hand the engine a size per frame and hands it four. A benchmark was written for a scenario that never happens. Three optimisations were tried against a slow layout and two of them did nothing. Take the measurement first and let it choose the work.
- **Say what is not done.** An item that is open is open, with its number and its cause. Do not describe an attempt that was withdrawn as if it shipped.
- **The user runs git unless they ask otherwise.** When they ask for a commit, it is one commit, amended rather than stacked, and the working tree is left clean.

## Commands

Everything goes through `python3 run.py <task>`:

- `test` — fetch a released engine into `.varn/` and run the Lua suite against it.
- `pack <dir> <out.vap>` — build an application archive from a project directory.
- `doctor <archive>` — validate an archive and report what is missing or unused.
- `sample` — pack the sample application into `sample/dist/`.
- `fetch-native` — download the released `varn.xcframework` and `varn.aar` the two mobile sample hosts link against.
- `shots` — screenshot every gallery screen in both appearances, on the iOS simulator and in a headless browser. `--platform ios` or `--platform web` for one of them, `--only` for the screens whose name carries something, and `--appearance` for one side of the look.
- `reference` — write the component table in `docs/components.md` from the declarations themselves, which is what keeps a component from documenting a prop it does not accept.

The other renderers run the same suite themselves: `node --test renderers/web/tests` for the web, `xcodebuild test` in `renderers/ios/tests` for iOS, and `./gradlew :app:testDebugUnitTest` in `apps/android` for Android. `python3 run.py serve` assembles the page and serves it, since a browser needs a server for its modules and for the wasm, and it packs the framework and the gallery again each time — they sit beside the page as files rather than as links, so a reload after a change in Lua would otherwise show what was packed before it.

## Architecture and organization

- **The renderer owns no policy.** If a renderer has to decide something, the decision belonged in Lua and three renderers will disagree about it. This is the rule the whole project rests on.
- **Layout is computed in Lua** and renderers receive finished frames, each relative to the node it sits inside, since a renderer adds a child to its parent and the parent's origin is already applied. Text measurement is the one thing that crosses back, because only the platform knows its own font engine.
- **A commit sends one batch of operations**, never a call per widget and never the whole tree. Lua holds the virtual tree, the renderer holds the retained one, and neither reads the other's.
- **The host drives the runtime with `load` plus `poll`** on the thread that owns the interface, so every `host.*` call lands there and a renderer touches its views with no dispatch and no lock.
- **Lua owns the window and the reuse pools, the renderer owns the scroll view.** A list realises its own cells as ordinary nodes, and a pooled cell keeps its identity in the element tree, so reuse is the reconciler patching a subtree rather than a second mechanism beside it. The renderer contributes a native scroll view with a `contentExtent`, reporting its offset. It keeps no window and no pool.
- **A style is resolved into concrete values before it crosses the bridge.** Resolution happens in `Runtime:resolveStyles`, never in the diff, so no renderer carries a theme and three of them cannot disagree about what a spacing step means. A new theme re-sends every node its style.
- **Nothing crosses the bridge that json cannot carry.** `gui/bridge/wire.lua` turns a handler into the marker `true` and the removed sentinel into `"__varn_removed__"`, and refuses a cycle. A function never travels — the renderer reports an event by the name of the prop that declared it and the runtime finds the function again on this side.
- **The safe area and the keyboard are layout inputs.** The runtime holds them and `SafeArea` and `KeyboardAvoiding` turn them into padding, so a screen avoids the notch and the keyboard with no platform check anywhere in the tree.
- **Layout per module**: `gui/<area>/` holds the framework, `gui/components/<name>.lua` a family of components, `renderers/<platform>/` a renderer, `apps/<platform>/` the sample host, `docs/` the reference. One file holds one context: the runtime is `gui/runtime/`, where what the engine reads out of a node, where a picture comes from, what a batch carries once the tokens are resolved and the keyboard each have a file of their own, and the runtime is one object those files add their methods to rather than four things beside each other.
- **An event's payload is what the event carries, and nothing wrapping it.** A value-changing event carries the value itself (`onChange(true)`, `onChange("typed")`), a scroll carries `{ x, y }`, a selection carries `{ item, index }`, and a press carries nothing. A renderer that wraps a value in a table is broken, and the conformance suite says so on all three.
- **Light and dark come from the platform.** The host reports the appearance with the surface and again when it changes, `Runtime:setAppearance` follows it, and an application that passed a theme of its own keeps it. An application never carries a switch of its own for something the reader already set on their device.
- **The chrome is the platform's own proportions.** A bar is 44 high, a list row 60, a section header 34, and the type scale is the theme's — a value chosen per screen is how a screen ends up looking like nothing else on the device.
- **Binding invariants:**
  - A diff never emits an operation for an unchanged subtree. A re-render that changes one leaf produces one update.
  - **Every prop written as a literal is compared by value, not just the style.** A style was, and the four props carrying a list of their own were not: an icon's `commands`, a rich text's `spans`, a picker's `options` and a segmented control's `segments` are each built afresh by the render that names them, so each was an update over the bridge on every commit for a node that had not changed. An index of twenty rows with a chevron each is twenty of those. They are all in `LITERAL`.
  - **A style is compared by value and kept by identity.** A style is written inline at the point of use and is a fresh table on every render, so comparing it by identity marks the whole tree as changed: an update per node over the bridge and a layout that can keep nothing. `gui/diff.lua` names those props in `LITERAL` and `carried` hands the previous table forward when the new one says the same thing.
  - **A handler is not a change a renderer can see.** It travels as a marker, so a fresh closure over the same event is the prop the renderer already holds. The tree still takes the new closure, since that is the one that reads the state the render was made from.
  - **A box keeps its layout across commits.** Sizing a container asks each child for its size, hands it a share and asks again, so a subtree is visited several times per level and a tree that is worked out afresh costs three to its depth. `gui/layout/flex.lua` keeps what a pass produced, answers a repeat of the same question from it, and rebuilds a box only when the layout node's revision moves. A rebuilt box invalidates the boxes above it, since they can no longer stand on a size that is gone.
  - **A layout node is compared on what the engine reads**, never on the props table it came from, and a resolved style with nothing in it is one shared table so a node with no style of its own never looks changed.
  - **A cell is handed over in the order its pool slot was claimed.** Every cell is placed by a frame of its own, so where it sits among its siblings is nothing a reader can see, and reading order would move every row on the screen each time the window slides by one. The order a batch asks for is worked out against what the renderer holds after the removals, since removing a child renumbers every child after it.
  - **What a control is worth is the platform's to answer.** A size written into the tree is a number that was true of one platform on one day, and the engine sends finished frames, so a control drawn larger than the frame it was given spills out of it. A type says its size is `natural.platform` and the runtime asks once, the same way and for the same reason it asks what a string measures.
  - **A box takes no touch of its own.** A screen is a tree of boxes, and one sitting inside something that can be pressed would take the finger meant for it and answer nothing. A box the touch stops at with nothing inside it wanting the point steps out of the way. A scrolling view always keeps its content inside itself: a view only receives a touch within its own bounds, so content drawn past the edge both overlaps what is above it and cannot be pressed.
  - **A press is answered the way the platform answers one**, on all three, since a control that does not react to a finger reads as one that is not listening.
  - **A component owns its look, and the theme owns the values.** A control with no look of its own draws as bare text on every platform, so each type declares the style it has in theme names and a declaration may compute it from the props a caller gave — which is what a button's variant, a divider's colour and a chip's selected state are. A renderer draws a plain widget the style paints, never one the platform has already decorated.
  - **A node is created with a style, even an empty one.** A renderer told nothing leaves its widget at the platform's own defaults, and a label drawn at a size the engine never measured is given a frame a few points short of its own text.
  - **An element in a prop is never mounted**, since only the array part of a spec becomes children. Anything that takes content — screens, sections, a panel, the cells of a table — is a Lua component that builds what it was given into the tree, never a host node handing data to three renderers that each have to know what to do with it.
  - **A screen names the file it wants and nothing else.** The runtime expands an asset name against the bundle, taking the density variant the surface is drawn at, and refuses a name the bundle does not carry. A source with a scheme is left alone for the platform to fetch.
  - **The props of one node arrive in no order**, since a batch carries them as a map. A prop that builds what a node holds is applied before one that chooses among it, or a control loses its selection on whichever batch happens to be ordered that way. A pair of props that decide one thing between them — the axis and the indicator of a scrolling surface — is held on the view and worked out again whenever either lands, never read from the other at the moment one arrives.
  - **A node is created before it is ever given a frame, so anything written against its own size waits for one.** An arrival is drawn on the frame rather than on the create: a view animated before it is placed has nothing to animate from, and a travel written as a share of the node resolves to nothing at all. That is one defect wearing two faces — a modal that appeared instantly and a panel that did not travel.
  - **A look is the runtime's per node, not per application.** Every style is resolved on the way out of the runtime, so a subtree in a look of its own is the runtime knowing which look governs which node. The index walk it already makes on every commit stamps each node with the look in force, `Runtime:themeAt` answers it, and everything that resolves a style, a colour, a run of stops or a tint takes it. A node whose stamp changed marks the tree to be painted again, so a `gui.Look` whose value changes reaches everything under it without any of them rendering.
  - **What a screen draws for itself is a screen's to say, not a stack's.** Nearly every application on a phone is a first screen carrying a band of its own and detail screens under the platform's bar, so `hidesBar` and `barStyle` belong to a screen beside its `titleView`, `trailing`, `largeTitle`, `scrolled` and `transition`, with the stack's as the answer when a screen says nothing.
  - **A field carries no box from the platform.** What the platform owns is the caret, the selection, the keyboard and every input method for a language that needs one. The box around them belongs to whoever wrote the screen, which is what `TextInput`'s own default style says, so each renderer clears the border, the ground, the padding and the face the user agent gives a field. Leaving it is a search pill with a second box sitting inside it on two platforms out of three.
  - **A transform's travel takes a percentage as well as a number**, and a percentage is a share of the node's own size. It is the only way a panel says it leaves by its own edge without the tree guessing at a height the layout works out, and it is re-read whenever the node's size changes.
  - **A layout leaves more behind than a size, and what a box may answer from memory follows from that.** It also leaves `pass`, which says whether a frame has to be sent, and the state of every box below it. So a box that answers from memory has to be left where a real layout would have left it, or it has to be certain nobody reads what it skipped. Three memos were written before this was clear and all three were withdrawn.
  - **A leaf may answer any question it has answered before**, since it holds nothing below it. It keeps its last eight answers, and answering one still runs `record`, so `pass` is set exactly as a layout would have set it.
  - **A container may answer a question only for the pass that is asking how large it is.** Sizing a container asks every child its size, shares out what is left and lays each child out for the share it was given, so the asking never decides where anything below the child sits and the layout that follows is what puts the subtree in agreement. An answer given there restores the size and nothing else — it leaves `laid` and `pass` alone and cannot survive the layout that follows. Without it a subtree is walked twice per level and a tree costs what it holds raised to its own depth: 2,615 real layouts a commit against 773, and a scroll in a split view at 14.9 ms against 5.7.
  - **What a box remembers is thrown away by whatever throws away what it last worked out.** A box that changes is rebuilt with an empty memo, but a box **above** one that changed is not rebuilt, so `build` clears its answers where it already marks it as no longer laid out. Without that a row keeps the width of the label it used to hold.
  - **Write a layout memo against the property test, never against a benchmark.** `gui/tests/layout_test.lua` lays sixty random trees out at ten sizes that come back around and compares every frame with a copy that has never been laid out at all, some of those boxes scrolling, since a box that scrolls asks its children something no other box asks. All three withdrawn attempts made a scroll several times faster and put things in the wrong place, and this is what said so. A second one grows a leaf in a tree already laid out, which is the shape a screen has and which the first cannot see. A hand-written case for that defect passed against it, because the row it measured was stretched by its parent and answered the container's width rather than its own — random trees find what a case chosen by hand was already shaped around.
- **What is shown over a screen is two layers and two moves.** A ground covers the screen and has nowhere to travel to, so it fades where it is. A panel travels, and that travel is what a reader reads as the thing arriving. Animated as one node the ground goes with the panel, so dismissing a sheet dragged the darkness down and uncovered the screen from the top. Every presented component is a fading `Presence` holding a travelling one, and `Presence` honours the style it is given so the panel is the node that moves.
- **A test says when it has finished, and the runner reads it back.** `async.run` schedules a body and returns, so everything after an `await` runs once the chunk has ended — and a second `async.run` in one file is never resumed at all. Both were true here, in four files, and the suite reported them as passing. Each test file has **one** asynchronous body, its `ok` is the **last line inside** it, and `run.py test` fails a file that prints no `ok`, that has two bodies, or that prints its `ok` outside one.
- **An application is told where it may write, and writes nowhere else.** A path relative to the working directory lands wherever the process was started, which is writable on a desktop and is not on a phone — so a picked file written that way works everywhere except the device it was written for. `gui.storage` is given the project's own directory when the application is launched.
- **Nothing that judges the gallery keeps a list of its own.** The screens `run.py shots` captures are asked of the catalogue, or a demo added to it is never looked at — which is what happened to four of them.
- **A margin moves a pinned box off the edge it is pinned to**, which is how a box of a known size is centred on one.
- **A screen that has been left is drawn leaving.** A caller derives its screens from what it is showing, so the one that was on top is gone from the list by the time the stack renders again. The stack is the only thing that saw it, so it holds it for the length of the move — put back where it was, and told to go on the commit after, since a node born in the state it is leaving in has never been anywhere else and there is nothing to animate.
- **What is pinned to an edge is pinned by the surface, never by the tree.** A commit follows a finger rather than leading it, so a header placed from Lua at the last offset it was told about drifts across the rows it is meant to cover on every flick. The tree says which node and over which range — `pinned = { from, to }` in content coordinates — and each surface holds it at `clamp(offset, from, to - extent)` as it scrolls, which is the push-out the platform's own lists have. It also takes a sticky list off the per-pixel commit it used to need.
- **A control that answers `noIntrinsicMetric` has no opinion about that axis.** Asking such a control to fit answers the smallest it can be drawn at, which is not an opinion: taking it made every slider on iOS 37 points across, a thumb with no track beside it. Only a control that answers nothing on both axes is asked to fit.
- **Being built and being seen are two different things.** A stack keeps the screen under the one on top and a tab bar keeps every tab, so a component that only hears about mounting loads work for screens a reader never looks at and goes on running behind ones they have left. Nine moments are reported — `onWillMount`, `onMount`, `onWillAppear`, `onAppear`, `onUpdate`, `onWillDisappear`, `onDisappear`, `onWillUnmount`, `onUnmount` — where the `will` half runs against the tree as it stands and the other half is held until the batch has reached the platform. Visibility is not something a subtree can work out for itself, so whatever is showing it says so with `gui.Showing`.
- **A ref answers rather than raising when what it pointed at has gone.** A ref is held across time — a timer that scrolls a list, a handler that focuses a field once an answer lands — and by then the screen may have gone. That is life rather than a mistake: the ref is emptied when its node goes and a call through an empty one answers no. Calling an action a component does not have still raises.
- **A test that is not in CI is a test that rots.** Half the browser suite and the whole of the suite that drives the gallery with a finger were run only by hand, and those are the ones that find what a tree-based case cannot. Both run in `check.yml` now, and the reference page is held to the declarations it is generated from.
- **A screen that asks for a commit from inside one for ever is stopped and named.** A component changing its own state from `onUpdate` is answered with another commit, which calls `onUpdate` again: the loop never idles, the device runs at full tilt with nothing moving, and nothing is reported. Fifty in a row is a mistake rather than a screen settling. A screen that converges after a few rounds is left alone.
- **Every declared type is one all three renderers can build.** The browser refuses a type it has no element for, so a component wired into two of them draws on two platforms and throws on the third. The check is derived from what the browser names rather than from a list somebody keeps.
- **A control that can be pressed says something.** A reader using a screen reader hears a control with no name, or nothing at all where one is. What a control holds counts, and one drawn as a picture carries its own words.
- **A failure inside a call the engine made never escapes it.** What a host registers is called from the engine's own frame, so an exception that escapes takes the process with it. All three answer the engine and report the problem instead.
- **A handler is set, never added.** A prop that comes and goes rebinds, so a listener added each time leaves a control reporting each event once per binding. One listener for the life of the view, and what it calls is swapped.
- **A view tag is not a place to keep anything.** Android refuses any tag key that is not an application resource id and throws where it is given one, so a key made from a string hash is a crash whose likelihood is the top byte of that hash. What a view has to remember belongs in a class of its own.
- **A batch is checked for what it carries as well as for what it names.** A width that is a string and an id that is a table both reach three renderers as something each reads as nothing, so every field of every operation has a type as well as a name.
- **A host that stops takes the tree with it.** Stopping the loop alone leaves every screen mounted, every timer firing and everything a node opened still open, on an interface nobody is looking at. Each host tells the engine it is finished and the tree comes down.
- **A number json cannot carry never crosses the bridge.** NaN and infinity both encode as `null`, which a renderer reads as no number and lays the node out at nowhere: a screen that vanishes with nothing said. A frame is checked before it is sent, the node keeps the one it had, and the problem is reported. The same guard already stood in front of a measurement.
- **Rendering a screen proves nothing about using one.** Every demo is rendered *and driven* — every press and every change a reader can make, with what the platform sends as the payload — and a problem reported while one is being used fails the suite. A handler that throws is where a screen actually fails, and a case that only renders it sees none of that.
- **A host gives back everything it set up to watch.** An observer on the page and a listener on what the reader set their device to go on reporting into an engine that has stopped answering. One signal for all of them, aborted where the pump stops.
- **Nothing that lands after the tree is down is half done.** A picture that arrives, a timer that fires, an event a host sends: every entry point answers nothing once `stop` has run, rather than building a tree from a root that is not there and reporting a failure for each thing that was still on its way.
- **What a node opened is given back when the node goes, and by nothing else.** Detaching is not removal: a cell that scrolls out of a list detaches and comes back, so a player closed there is a sound that never plays again and a map whose fetchers were shut down never draws another tile. The renderer knows when a node has gone, so that is where the release happens, and detaching only stops what is ticking.
- **A move is a detach, so `onDetachedFromWindow` may not end anything.** The Android renderer performs both `insert` and `move` as `removeView` followed by `addView`, and a node moves whenever its place among its siblings changes — a list that reorders, a screen that is pushed, a child that appears above another. Four views took the detach for the end of their life: a sound stopped reporting its position for good, a recording in progress was dropped without ever answering `onFinish`, and a video and a camera released a second time behind the `TextureView` callback that had already done it. Nothing is released there. What is ticking is tied to what it reports on rather than to the window, and the release belongs to `remove`, which the engine's own unmount reaches through the batch.
- **A platform notice with no object is every object.** `AVPlayerItemDidPlayToEndTime` is raised by every item in the process, so a sound and a video observing it with `object: nil` were each told they had finished whenever the other one had — `onEnd` for a node halfway through, and a looping node restarting because something unrelated ran out. An observer matches the notice against its own item.
- **A handler is bound before anything that can report through it.** Applying a prop can report before the batch is over — a source that cannot be opened is refused where it is set — so a handler applied afterwards is one whose only word about it went nowhere. Android orders a batch's props: handlers first, then what a control is made of, then the rest.
- **A `when` arm by a name another arm already used is dead, and a renderer routes by name.** Kotlin runs the first arm that matches, so a second `"onSelectionChange"` for the editor sat under the field's and never ran: the row of tools over an editor lit up for nothing on that platform. One arm answers for every control that carries the name. `promises.shadowed()` reads that `when` alongside the browser renderer's run of checks, and the compiler's own `Duplicate branch condition in 'when'` is a failure rather than a warning to scroll past.
- **Anything answering from off the main thread checks that what it answers is still there.** A tile that arrives after the map was released, a permission a reader granted after the screen was left, a fix that came back late. Each of those reaches a view that is gone, and each is dropped rather than delivered.
- **The half of the lifecycle that runs inside the diff is guarded like the half after it.** A component whose `onWillAppear` throws would stop the whole tree being built rather than only itself, so each of those is run through a pcall and reported the way a callback after the commit already was.
- **One arrival at a time.** Everything inside a pushed screen is mounted in the same commit as the screen, so a child with an arrival of its own adds its travel to the screen's and the pair comes in diagonally. A node mounted inside something that is itself arriving is built where it belongs and moves with it. The batch that builds it leaves the arrival out, the retained props keep it, so the next comparison sends nothing.
- **A field is not written back to anything it said itself.** A tree answers a keystroke with the value it has just been told, and by the time that lands the reader has typed two more: "Are you there" arrives as "Are you r". Each field keeps what it has reported since it was last written to and ignores all of it, and anything it never said is a real change that clears the history.
- **`table.unpack` anywhere but last is cut to its first value.** A conversation drew one bubble and nothing after it. Build one list and unpack it at the end.
- **A tablet is not a large phone, and the difference is read from the breakpoint.** A bar is 50 tall on iOS at a regular width against 44 on a phone, a screen keeps 20 at its edges rather than 16, a run of text is capped at a width somebody can read, and what is shown over a screen is centred in a panel the width of a form sheet rather than covering the whole of one. All of it lives in `gui/style/chrome.lua` beside the bar heights, and nothing anywhere reads a device name to get it.
- **A box that does not clip its drawing does not clip its touches.** A view answers a touch only within its own bounds on both phones, so a child drawn past the edge of the box it belongs to is seen and never pressed — the raised picture on a tab bar is the case that found it. What is drawn outside is meant to be pressed, and a box that clips its drawing clips its touches with it.
- **Anything on screen may be told to let a finger through it.** `pointerEvents` is universal, like a key, a style and a label: a picture drawn over the control that chose it is not meant to take the press aimed at it, and a component that has to declare the prop first is a render that throws on the screen a reader is looking at.
- **A failure a reader can see is something they can put away.** The sample hosts drew a problem into the view as a label that stayed for the rest of the session, carried from screen to screen. A banner with a way to dismiss it, or the platform's own toast.
- **A control claims a finger that landed on its own drawing.** A plain view takes a touch on iOS whether or not it has any use for one, so an icon inside a tab swallowed every press aimed at it — the bar looked right and answered nothing, and landing beside the icon got through, which is a control pressed three times to be heard once. Anything inside that answers a finger of its own keeps it, and everything else hands the press to the control it is drawn in.
- **A press is given up to the gesture that beat it, never to a distance.** A finger on a phone is never still and a control inside a list moves under one that is, so a press held to a travel of its own is a control a reader presses three times to be heard once. The platform already arbitrates this: UIKit answers a press wherever the finger is lifted inside the control, Android gives one up when the touch leaves the view, and a swipe recogniser cancels the touches it recognised on. Only the node the tree asked a swipe about gives its press up to one, and a browser suppresses a press only for the node that was actually swiped, never for a click the keyboard raised.
- **A sound is silent until the application says playing is what it is for.** A phone on silent plays nothing through the default session, and most phones are on silent, so the session is set to playback the moment a sound or a video is given a source.
- **Written into a demo is not drawn by one.** A check that searched the demo sources for a component's name passed a player that was declared in a file the gallery loads and put into no screen at all. Every demo is rendered, every switch on it is turned on, and the node types that come out are what the check reads.
- **A scrolling surface hands a touch straight to what is inside it, and asks for it back.** A `UIScrollView` holds a touch to see whether it is a scroll, which delivers a press late and swallows a quick one, so `delaysContentTouches` is off and `canCancelContentTouches` is on, the way the platform's own lists have it. Android is the mirror image: a child that answers a press consumes the whole gesture, so a surface with no `onInterceptTouchEvent` does not scroll at all over its pressable rows, and it takes the finger once the drag passes the platform's scroll threshold.
- **A press with no finger behind it is still a press.** A click raised by the return key on the web carries no pointer, so nothing about the last gesture's travel applies to it — suppressing it is a control that cannot be reached with a keyboard at all.
- **A finger that travels is not a press, and every renderer has to say so.** A control on iOS fires when a drag ends inside it however far it went, a view on Android gives up a click only when the touch leaves its bounds, and a browser raises `click` for any pointer that goes down and comes up on one element. All three let a swipe across a row open it. Each is held to the distance its own platform allows a tap.
- **A press, a hold and a swipe are three things.** `Pressable` reports `onSwipe` with the direction the finger went, since an item does something different for one.
- **An interface that changes shape is one tree, not two.** Rendering a split where there is room for both and a stack where there is not means a turn of the phone crosses between two trees, and everything under either is taken down and built again — a reader loses what they typed for having held the device sideways. Both panes stay mounted, keeping their place and their keys, and only their layout changes. `SplitView` does that, and a stack at its first screen takes `onBack` so the collapsed detail column still has somewhere to go.
- **A stack keeps every screen it holds, and shows only the top one.** `NavigationStack` renders every screen up to the index, the top one in the flow and the rest exactly where they were, covered, undrawn and taking no touches. Rendering only the top unmounts everything under it, so coming back is a screen that has never been used: a list at the top, a field emptied, a form that forgot. Leaving the covered ones **drawn** is the other half of the same mistake: a screen is not required to paint a background, so the shop's grid read through the product page over it and the checkout over both. Held, not shown. It costs a covered screen per commit, which is 5.7 ms against 6.5 ms on a split-view scroll.
- **`x and y or z` is a Lua bug wherever `y` can be false or nil, and it reached the core.** `setState` was written `value ~= none and value or nil`, so **every state a screen set to false was stored as nothing at all** — it reads as false everywhere except against false itself, which is where it surfaced. The headless renderer had the same line for a prop arriving in an update, so every test asking whether a prop is false after one was weaker than it looked. Write the `if`.
- **A control the platform sized on an axis is not stretched along it.** A switch is fifty-one points across because that is what a switch is, and one stretched down a tablet is drawn in the corner of a box the width of the pane with every point of it answering a finger. A platform with no opinion about an axis answers nothing for it — a slider, a segmented control, a dropdown — and those fill the room they are given. The rule was written twice, once where a child is measured and once where it is placed, and only one copy knew: **one question, one answer, asked once.**
- **A shape only one platform has is not a prop.** A date picker's wheel is an iOS control: the browser draws one date field whatever it is asked for, and Android's spinner needs a theme chosen before the widget exists. Offering `display` meant two of the three answered nothing for the shape they lack and drew the control at no height at all — an invisible field in the sample's own demo. The tree asks for a date and each platform draws the control it has, `gui_measure_control` asks about the type alone, and a control the platform sized on both axes says so with `alignSelf` rather than being stretched.
- **A runtime can be taken down.** `Runtime:stop` unmounts the tree, which fires every `onUnmount` and so ends every timer a screen asked for. Without it a screen that repeats something holds the engine's loop open for the life of the process, and a test that mounts a demo and walks away leaves it running — which is what stopped the suite terminating.
- **A component built from the others is not a node three renderers have to know about.** A chip was a host type that every renderer drew as a text box, so a `removable` flag would have been three drawings of one glyph. It is a pressable pill holding its label and the mark that takes it away, and the `chip` type is gone from all three. The same reasoning made a skeleton lines rather than one flat box.
- **A key says two nodes of the same type are different things, wherever the node sits.** A component's own root is compared with nothing above it — there is no key lookup the way there is among siblings — so comparing on the type alone made it immune to its key and it was patched in place rather than replaced. Nothing about it was new, so `enter` was never applied: every overlay, drawer and pushed screen arrived in one frame while the way out of them animated correctly. `Presence` is built on exactly that change of key.
- **A frame writes only what the style names.** A node is framed again in the commit after the one that creates it, and a travel written as a share of the node has to be re-resolved when its size changes — but a node arriving carries its travel in `enter`, not in its style, so re-resolving from a style naming none reset it and the arrival had nowhere to come from.
- **A box told to take no finger takes none for anything inside it either**, on all three. Stopping the box alone leaves every control within it answering a press that should never have reached it, which is what a covered screen in a stack is made of. On Android that means refusing to dispatch, so the platform carries on to the next sibling rather than swallowing the touch.
- **Padding is declared in one place.** A control that draws its own text is inset by its **style**, which is what the renderer reads, so that is where its padding lives. `natural.padding` is for room a renderer needs for a part it draws itself — a checkbox's box — and a type that declares both has its padding counted twice: a badge of one digit came out 32 across for a pill that is 20.
- **What a type is never smaller than is a floor on the box, not on the text.** Applied to the text it is the padding over again. A badge's `minWidth = 20` means the pill is twenty across.
- **A gesture that leaves a screen is an edge gesture, and it acts when the finger lifts.** A swipe recogniser over the whole surface takes a drag on a checkbox, a slider or a carousel as a request to leave, and it fires the moment the movement passes its threshold, so the screen goes while the finger is still down. An edge pan, acted on at `.ended`, past a distance or a speed.
- **A screen says nothing about the system's own bars unless it means both appearances.** Every platform draws them from the appearance already, so a tree that names nothing follows light and dark for free. The sample named `light`, which read correctly in the dark and put white glyphs on the white bar the light appearance turned it into. `barContent` pins it, and belongs only on a screen whose bar keeps one colour either way.
- **A mark is drawn, never written as a character.** A glyph like `⌃` is a different shape and a different size in every platform's font, and inside a `numberOfLines = 1` text it is the first thing a long title truncates away. The engine ships an icon set for exactly this — a table's sort order, an accordion's state, a row's chevron.
- **A surface draws a bar only for the axis it scrolls**, and a paged one draws none at all, since it says where it is with its dots. One prop applied to both axes gave every vertical list a horizontal bar it has no use for.
- **What is inside a scrolling surface travels with what it scrolls.** A carousel's dots were children of the surface, so they were only ever seen over its first page. Anything that has to stay put is a sibling over it.
- **A view that reads a whole batch reads it once.** A centre, a zoom and a set of marks describe one region between them, so a map told each of them separately moves three times for one change, and a location node asked again for every prop asks the reader for a permission again. The renderer applies a batch and then settles the node — `VarnSettling` on iOS and Android, `settle()` on the web — and a frame settles it too, since how much of the world fits depends on how wide the map turned out to be.
- **A platform that reports a change does not always say who made it.** MapKit reports the region changing when a reader drags the map and when the map re-fits itself to a new size, and taking both as a reader's move means the tree is told its own props back and the map fights itself on every commit. The gestures are watched alongside the platform's own reporting, and only a reader's move is passed on.
- **A map is drawn in tiles, and only one platform gives you one.** The zoom is the one every raster map on the web is cut in, so a centre and a zoom mean the same thing on all three. Apple gives MapKit away, and Android's own map is Google's — a dependency, a key and an account before a screen can show a street — so the Android renderer and the browser draw the tiles themselves and credit OpenStreetMap on the map, which is what its licence asks. MapKit thinks in degrees rather than in tiles, and a degree of longitude covers less ground the further from the equator it is, so a span worked out without that is widened rather than refused and the map sits at a zoom nobody asked for.
- **A capability the device grants is asked for by mounting the thing that needs it.** A `Location` is on screen for as long as a screen wants a fix and takes the receiver with it when it goes, so nothing runs behind a screen a reader has left. A refusal is reported through `onError` rather than left waiting, and on Android a permission belongs to the activity, so the renderer asks the host for one the way a file chooser does.
- **Something a reader is given a piece at a time is reported a piece at a time.** `onPick` reports one file per call, since gathering a set of photographs puts the bytes of every one of them into a single message that is decoded and written in one turn of the loop, and nothing moves until the last one lands.
- **Every event from the host reaches the tree inside a guard.** The engine calls a subscription from its own delivery, so an error there is written to the engine's log and to nowhere a reader can see, and the surface stops answering with nothing said. A resize, a keyboard, an appearance, a back press, a font, a touch: each is handled through a guard that reports through `onProblem`, which is what the commit the host arranges already did.
- **Reporting a failure cannot fail.** `Runtime:report` is where everything contained ends up, and it is reached from the middle of a commit, so a listener written by the application that raises turns the containment path into the failure it exists to contain. The listener is offered the problem and the log takes it when the listener will not.
- **A page never throws across a wasm frame.** The engine calls the browser from inside one, and a JavaScript exception raised there unwinds frames no C++ handler can catch: the call never returns, the Lua stack is left mid-call and the runtime is dead with the page still standing. Every registered call answers something and reports what went wrong, and telling the reader cannot throw either.
- **A problem is shown over the application, never in place of it.** Writing one into the container takes the screen away for good — the renderer's nodes are gone and every id it holds names an element that is not there — so one failed handler would end the session. A banner over what is drawn, with the count of what came before it, and a way to put it away.
- **A repeating action runs only while it can be seen.** A tab bar keeps every tab and a stack keeps the screen under the one on top, so `self:every(...)` tied to being mounted alone asks for a commit every few hundred milliseconds behind whatever the reader is looking at. A turn taken out of sight is skipped rather than ended, so the pulse is there again on coming back, and a carousel told to play waits the same way.
- **`self:visible()` is there for any component, whether or not it declared a moment.** Asking it costs nothing: a component with a visibility callback is made a reader of the value, since the moment is fired from the render that follows a change, and one that only asks is answered without being rendered for something nothing draws.
- **A host event is delivered by the loop, so a host that stops gives it the tick to do it on.** `emit` posts the delivery rather than making it, so emitting `gui.stop` and taking the pump away in the next line is a tree that never comes down: every screen still mounted, every timer still firing, everything a node opened still open. Emit, poll, and then stop pumping.
- **A host gives back everything it set up to watch, on every platform.** A notification observer registered with a block is keyed by the token the call answers rather than by the object that took it, so removing by object removes nothing, and a listener nothing keeps can never be taken off at all. Each host keeps what it registered — observers, recognisers, layout listeners — and hands all of it back in `stop`.
- **A host is where the tree meets the platform, so it is tested like one.** A fake engine recording every call in order holds what matters: the tree comes down on a tick the pump is still there to take, a notification after `stop` reports nothing, and the surface is left as it was found.
- **What every screen draws from is held once, not per view.** A map's tiles are the same picture for every map and for the next screen to open one, and the service they come from asks a client to keep what it was given, so throwing them away with the view re-fetches the world on the way back. One store for all of them, given back when the platform says memory is short.
- **A default is the library writing a prop, so it is not proof the caller wrote one.** A mutual exclusion checked after defaults are filled in refused every use of the other prop: `minColumnWidth` raised on every grid that used it. Where two props are alternatives, neither carries a default and the fallback lives where the value is worked out.
- **A colour a control carries is a prop, and the engine paints every one of them.** A renderer reads a colour and parses nothing, so a theme name that reaches one is a control painted in nothing at all — `placeholderColor` was sent as the word `textMuted` for as long as it existed. What a caller may name, the engine turns into a colour, and the suite asks that of every prop whose name says it carries one.
- **A style field is honoured by all three renderers or it is not a style field.** A line limit, a picture's tint and a placeholder's colour are props: only iOS ever read the first from a style, so writing any of them there was writing something two platforms ignored. Each renderer is asked in the language it reads a style in — a subscript on iOS, a json field on Android, a field of an object on the web.
- **The window a list scrolls through is held by its own invariants.** Where an entry sits and which entry sits at an offset are the same answer read from either end, and rows of different heights are arithmetic nobody checks by eye. Two thousand of them, measured and estimated, driven from both ends every run.
- **The reconciler is held by a property test, not by cases.** A screen inserts, removes, moves, replaces and re-keys at every depth at once, so that is what is driven: eighty random mutations a run, the renderer's tree compared with the description node for node after every commit, and no batch allowed to name what it removed. A case chosen by hand tests what its author already thought of.
- **What is held against an edge keeps its order as well as its place.** A row realised while a surface scrolls is inserted where the tree puts it, which is under the header it belongs to and over it on the screen. The browser gives a held box a z-index and is done. The phones reorder, so they raise it when something loose has landed above it — never on every frame, and never from inside the walk that reorders, since `bringToFront` moves the child to the end of the array being walked.
- **A public call is documented or it is not public.** `gui.none`, `gui.environment` and `gui.context` were reachable, used and written down nowhere. `gui.resolveStyle` was reachable and called by nothing but the suite, which can require the module: an export with no caller is surface nobody asked for.
- **Everything crossing into the engine is checked where it arrives, named, and never at the arithmetic.** This is the rule the most defects have hidden behind, and it has four faces.
  - **From a caller, in a value.** A minimum column width of nought is infinitely many columns, which is a frame that never returns. An extent of nought is every entry at one offset, a stepper's step of nought takes the process down on iOS, and a rating of a million marks is a drawing per mark. An autoplay, a toast or a duration of nought is a timer refired as fast as the loop will run it. A size, a padding, a gap, a corner or a border below nothing reaches three renderers that each make something different of it, and a `grow` written as a word fails inside the arithmetic that shares out the room — a margin and the four offsets are the exception, since pulling a box outside the one that holds it is how a panel wider than its anchor is centred. `rgb(255, 0)` read as far as it goes is arithmetic on a nil three files away, and a directory named `..` is a file written where the host never said it may be.
  - **From a caller, in a shape.** A handler that is not a function is a control that looks pressable and answers nothing. A key that is a table never matches what the last render built, so the node is replaced on every commit and everything under it loses its state. A label's text is a string, since a measurement asks a number for its length and a renderer draws it as nothing. A label, a test name and a ref have one shape each, and a style is a table. All of it at the call site.
  - **From a caller, in what a component cannot do without.** A section list draws a header for every section, so one built without `renderHeader` failed on the first section it reached, naming a line of the list machinery rather than the list somebody wrote. Ask for it where it is declared.
  - **From a host, which is a platform's arithmetic rather than a careful table.** A surface, a safe area, a keyboard height and a theme are all reported, and one that answers a width as a word lays every box out against it. A payload carrying a number that is not finite is dropped and reported rather than delivered, since a scroll offset of `nan` reaches the window that decides which cells exist. `gui.start` is where the two meet: a description that is not an element and a surface that is not two numbers are refused there.
  - **And a colour is painted whatever shape it was written in** — a name, a literal or a table of channels, all turned into the hex a renderer reads, anything else refused. A theme is built from families of names, so `colors = "blue"` is refused rather than answering nothing for every name a screen asks for.
- **The page is a folder a static host serves as it stands.** `apps/web` carries the engine, the framework, the archive, the renderer and the icon, so nothing it loads climbs out of it — an import that does is a white screen and a 404 in a console nobody had open. Assembling it follows `host.js` through what it imports rather than a list, and refuses a page that reaches outside the folder that is served, which is the question a browser asks rather than the one a filesystem answers. The suite drives the host out of that folder too, so what is tested is what is served.
- **A control is measured as the control the renderer will draw.** The browser's probe built a bare element of the right tag, which carries neither the rules the stylesheet keys on the type nor the parts the control is built from, so a switch answered 13 by 13 and a stepper, a segmented control and a rating each answered nothing at all — every one of them drawn at a size no control on the page ever has. One builder makes the node and the probe, the way `VarnViewFactory.make` answers both on iOS. Measuring appends an element and reads its box back, which lays the page out again in the middle of a frame, so each type is measured once and the answers are dropped when a font arrives.
- **The page positions nothing.** The engine sends finished frames and the renderer places each node it is given, so a rule in the page that positioned everything inside the surface reached the parts a control is built from — the box and the words of a checkbox, the buttons of a stepper, the segments of a picker — and stacked them all at one corner. Every node the renderer creates is positioned by the renderer, inline, and nothing else may.
- **A control the browser has none of carries the metrics the phones draw it at.** A switch drawn by a rule has no size of its own, a control built out of parts is only as large as the parts that happen to be in it, and an appearance reset leaves a range input as tall as its track rather than as the thumb on it. The numbers are named once in the stylesheet — 51 by 31 for a switch, 94 by 32 for a stepper, a 32 tall track for a segmented control — and a frame arrives on the element itself, which wins over every one of them.
- **A renderer writes its own words in the colour the platform writes one in.** The caption of a checkbox, the date inside a picker and the title on a chooser are named by no style, and a browser's default is black whatever the application's theme is. The surface is put in the appearance the system reports and its text colour is the system's own, so those words follow the theme rather than staying black on a dark screen.
- **A control the browser draws for a form is given the shape it has in an application.** A date and a time read as fields rather than as boxed inputs, a colour as the swatch a phone shows, and a file chooser is the button its caller titled with the browser's own chooser hidden inside it — an input drawn as it comes carries a caption of the browser's choosing, in the browser's language rather than the application's, and drops the title it was given.
- **A box held against an edge is followed by the surface, never moved from a scroll event.** A scroll is answered by the compositor and the event arrives after the reader is already looking at the next frame, so a header positioned from one trembles across the rows it covers. The browser is told the range to follow the surface over and how far to travel across it, and drives the rest itself.
- **A word an input method is composing is not text yet.** A reader writing Japanese, Chinese or Korean types the sound of a word and picks it out of what the platform offers, so writing the tree's own value over the field takes the half-written word away and the return that picks one is not a return that submits. All three check it in their own terms: marked text on iOS, a composing span on Android, and a composition the browser reports.
- **What a style does not name is cleared, never written as nothing.** A control the browser has none of is drawn by the stylesheet, and an element that writes `border-style: none` onto itself cannot then be given a border by a rule: every spinner on the page was a ring nothing drew. The chrome a user agent puts on a control it owns — a button's face, a field's border — is taken away by a rule as well, in one place, rather than cleared on the element where the next style pass clears the clearing.
- **A gesture lasts from the pointer going down until it comes up.** It belongs to the pointer that started it, and a pointer holding nothing is one crossing the page rather than one working a control. Watching a move without either was a swipe reported minutes after the press it belonged to, on a control nobody was touching.
- **A picture is fetched and a player is handed an address.** A phone hands an `https://` string to its image view and quietly draws nothing, so the engine fetches a picture and answers a local file. Every platform's player streams an address itself, so a video or a sound is given the address as it stands — downloading a film into memory to hand it over as bytes is a page a browser refuses outright and an element left with nothing to play.
- **Everything a host tells the engine crosses on the host's own pump.** The engine unwinds its stack to wait and rewinds it from a callback of its own, so a call raised from a click or a resize in between lands in a stack it is halfway through rebuilding. One place, one moment.
- **The theme carries the classic colour families at the tones they are published in**, so a screen may name `indigo400` or `red` directly, and the roles a component reads are chosen from them. A name the theme knows is the theme's rather than the browser's.
- **An address names a screen, and the host reports it.** A deep link, an app link and a web address all arrive as one string, at start and while the application runs, so nothing above a router knows which of the three it was. A scheme of an application's own names no machine — `varn://items/3` is the path — while the web's schemes carry a host that is read off and kept rather than matched on. A browser keeps the address in its own history, which is a capability the host declares rather than something a phone is asked for.
- **A component is declared once, never inside a render.** One declared in a render is a different kind on every commit, so what it drew is torn down and built again each time: the screen comes out blank and nothing at all is reported. It is refused where it is written now, which is the only place the mistake is visible.
- **A value a screen binds to is read from the render that draws it.** `gui.observable` remembers which components read it and draws those again — not the one that happens to own the screen and everything under it. Writing what is already there is not a change, a component that has left is dropped rather than marked dirty in a tree it is no longer part of, and anything that is not a component subscribes and lets go.
- **A bar is the library's, not each screen's.** `AppBar` draws what the system draws — the height, the title's placement and the way back all read from `gui/style/chrome.lua` — and `Scaffold` is the arrangement around it. The navigation stack draws its own bar with the same component, so there is one bar rather than two that drift.
- **A line is a multiple of the size, on every platform.** The browser read it that way, iOS handed it to `lineHeightMultiple`, which is a multiple of the face's own line, and Android multiplied the paint's font spacing by it — three meanings for one number, so one tree came out a different height on each. The conformance case pins the number rather than asking for "taller".
- **The theme's typography is what a string is drawn in, and what it is measured in.** A face and a line named in one place is one tree drawn one way everywhere, and it is also what keeps a measurement honest, since both read the same style. The framework ships Roboto and registers it before the first layout, so nothing is drawn in whatever each platform calls its system font.
- **A pointer is not a finger.** `onHoverIn` and `onHoverOut` report a mouse, a trackpad or a stylus arriving over a box and leaving it, and every platform underneath raises the same pair around a tap — so each renderer tells the two apart before it reports, or a row lights up under a finger and stays lit. A key event of its own is deliberately not built: it needs one contract for what a key is called across three platforms and a notion of focus the tree does not have.
- **Anything the tree listens to a press on is reachable from a keyboard.** A browser gives that to the controls it drew itself and to nothing else, so a row built out of a box was one a reader with no pointer could not open at all. A pressable box takes a tab stop and the role it plays, and answers a return and a space the way a button does.
- **A fold is a resize.** A folding phone opened, a tablet, a window shared with another application and a phone turned sideways are one thing to a tree: a width that changed. The screen rearranges around the new width and keeps what the reader had already put into it, which is what a test has to prove — a tree rebuilt from nothing looks the same in a screenshot and has lost everything. A hinge as a thing to lay out around is not read, since the only platform with an API for one is Android's `androidx.window` and every application consuming this renderer would have to carry it.
- **A measurement asks the platform's own text engine, never arithmetic that stands in for one.** Dividing a string's width by the bound counts the lines it would take if its words packed perfectly, and words do not pack perfectly: the browser breaks the same words on the same spaces with the same font, and Android asks `StaticLayout`, which is what a `TextView` draws with — it used to answer the paint's line spacing whatever the string said, so a label written in three lines was measured as one and drew over what came after it. A line break is a line on all three, which means the browser keeps what it was given rather than collapsing a break into a space and a run of spaces into one.
- **A node out of flow is placed inside the box that holds it.** There is no positioned ancestor to look for, since there is no `position: relative` and every box is one to be placed against — which is also what makes every frame relative to the node it sits inside on all three renderers.
- **A canvas draws a fill, a stroke or a text, and is told nothing else.** All three renderers walk the instructions and draw the three they know, so one none of them knows is drawn by none of them and reported by none of them either. The shape of each instruction is checked where it is written — the points inside a path are not, since a chart is a thousand of them rebuilt on every render.
- **A style carries only fields something honours.** A misspelled one crosses the bridge to three renderers that each ignore it, so a caller who wrote `colr` sees a box with no colour and is told nothing. `gui/style/resolve.lua` declares every field the layout, the runtime and the renderers read, refuses anything else by name, and the suite holds that list to the fields the layout itself reads.
- **What is on the path that draws costs nothing per entry.** The measurement store walked all five hundred of its entries to find the coldest one, which is 23 microseconds an insert and a millisecond of every frame of a scroll that measures fifty new strings. Two generations, retired whole, hold the same bound at half a microsecond — measured both ways, and the test fails against the old cost.
- **A control the platform refuses to be told piecemeal is told once the batch is in.** `UIStepper` raises when a bound crosses the other or a step is not positive, and a json object carries its fields in no order, so a minimum written before its maximum is the process gone. Bounds and value are read together on settling, on all three, or a value is clamped against whichever bound happened to arrive first.
- **A screenshot waits for the screen, never for a length of time.** A map draws its tiles, a web view loads its page and a picture arrives from somewhere else, all after the first frame, so a shot taken on a timer is a blank screen the tool invented rather than one it found. `run.py shots` looks until the screen stops changing, with a ceiling for the ones that never do.
- **A test waits for the thing, never for a length of time.** Forty milliseconds is plenty on an idle laptop and not enough on a machine building for a phone, and a gate that fails for a reason nobody can reproduce is a gate nobody trusts. `gui/tests/waiting.lua` runs the loop until it has happened. The exception is a test proving that nothing happens, which has nothing to wait for but the time.
- **A `WKWebView` answers a copy of its configuration.** Writing a preference on it after the view exists changes nothing, so a tree that said no to scripts was shown a page that ran them. What a page may do is decided per navigation, which is where the platform puts it and where the browser puts it too.
- **A warning the compiler prints is a defect it found for free.** Five props handled twice in one switch, a nullable answered where a string was expected, an API deprecated for a reason: each was said on every build and read by nobody. A build that says nothing is the only one worth reading.
- **Measure the thing that happens.** A rotation was assumed to hand the engine a size per frame and does not — UIKit sets the final bounds at once and animates the presentation layer, four reports for a full turn. The freeze was in scrolling, which nobody had timed.
- **A performance claim is a measurement, not a hunch.** Three of the four things tried against a slow rotation did nothing, and one of them was slower. The profile named a line nobody had suspected. Measure, keep what moved the number, and write down what did not.
  - **A performance budget is a test, not a hope.** `gui/tests/performance_test.lua` fails when re-rendering the index sends anything at all, when a keystroke costs more than four operations, when a uniform list scrolling one row costs more than twelve, when a scroll reorders a cell that did not move, or when a tree twenty-four deep measures its one string more than a handful of times.
  - A keyed child survives a reorder with its state. Identity comes from the key when there is one and from position when there is not.
  - `setState` schedules a commit and never runs one. Ten calls in a handler produce one diff.
  - A `setState` from inside `render` is an error, not a second commit.
  - The measurement cache is keyed by every input it depends on, and is dropped when a font is registered or the scale changes.
  - A list reuse pool is per item type. A cell of one type is never handed to another.
  - An archive is expanded once into a cache keyed by the hash of its bytes. A partially written cache is discarded rather than trusted.
  - A renderer declares its capabilities at start, and `renderer:can(name)` is how a caller reads one before asking for it. There is no helper that refuses on a caller's behalf: one existed, nothing ever called it, and its only test exercised itself.
  - **An index in a placement counts the siblings the node is not among.** A renderer detaches the node before it reads the index, or a move to a later position silently does nothing. The conformance suite catches this, and it caught it once already.
  - A component declaring a prop it does not accept is impossible: `docs/components.md` is generated from the declarations themselves by `gui/tools/reference.lua`.
  - Every component the library exposes appears in the sample application, which `gui/tests/sample_test.lua` enforces by name.
  - **A `nil` in the array part of a table cuts the list short at that point.** A conditional child is appended to a list rather than written in place, and a state field is cleared with `gui.none` rather than `nil`, which `setState` would never see.
  - A control with a size of its own does not shrink. A switch is the size the platform draws one at, and squeezing it to make room for a long label leaves something nobody can recognise or hit.
  - A handler runs after the commit, never during one — a list queues what appeared and disappeared and flushes it in `onUpdate`, since a handler is free to call `setState` and a commit may not start inside a commit.
  - `onLayout` is answered by the engine's own layout rather than by a renderer, so a renderer ignores that prop.
  - **Every colour is resolved to `#rrggbbaa` before it crosses the bridge.** A renderer reads a colour rather than parsing one, so a theme name, an `rgb` call and a three digit hex all arrive in the one shape. Three parsers meant three chances to disagree, and two of them read nothing that did not start with a hash: the theme's `overlay` is an `rgba` call, so the scrim behind every overlay was invisible on both phones and an alert read as the page it was covering. A colour carried as a prop — a switch's tint, a slider's track — is resolved the same way as one in a style.
  - **A change a reader is meant to follow takes time.** A node carries a `transition` and every later style change is drawn over it. Only opacity and the transform animate, so the frames the layout worked out are never disturbed. An easing is defined once as four cubic-bezier control points and sent as those four numbers, which is exactly what `cubic-bezier`, `UIViewPropertyAnimator` and `PathInterpolator` each take, so no renderer ever interprets a name.
  - **Something leaving is held until it has left.** A node removed from the tree is gone the moment the commit lands, so an overlay dismissed by a handler would vanish rather than animate away. `gui.Presence` keeps what it carries mounted for the length of its exit, hands the renderer the state to animate towards, and only then lets go.
  - **The chrome is the system's own, and it is the only thing that reads the platform.** `gui_surface` carries a `platform`, the runtime provides it above the whole tree, and `gui/style/chrome.lua` is the one file that reads it: a bar is 44 tall with a centred title and a chevron carrying the previous screen's name on iOS, and 56 with a leading title and a bare arrow on Android. Layout, styling and behaviour stay free of it, and a component reading it to pick a colour or a size is doing it wrong.
  - **A scroll view is asked to change nothing that has not changed.** `UIScrollView` lays out on every change of its offset and writing `contentSize` makes UIKit clamp the offset again, so re-assigning the same size fought the rubber band on every frame — a list that trembled wherever it was pulled past its last row.
  - **A scroll that puts nothing new on screen costs nothing.** A platform reports every pixel a finger moves and a commit lays out the whole tree, so a list returns early unless the realised range actually moved.
  - **A scrolling type owns its own overflow.** A style that names none may not clear it, or every list carrying a style stops scrolling — which is what happened to every list in the gallery on the web.
  - **The engine fetches a picture, not the renderer.** A phone hands an `https://` string to its image view and quietly draws nothing, so a remote source is fetched once with the engine's own http client into the archive's cache and every renderer is handed a local file. A renderer that shares no filesystem with the engine declares `imageBytes`, the way it already declares `fontBytes`, and is handed a data URI instead. Redirects are followed, since every picture service answers with one. The placeholder is what is drawn while a picture is on its way and what stays when it never comes, and the engine reports `onLoad` and `onError`, since the engine is what knows.
  - **The keyboard is something the tree is responsible for.** Done takes it away and `next` does not, a press outside what is being typed into takes it away, a drag on a surface that asked for it takes it away, and a focused field the keyboard would cover is scrolled clear of it from the frames the engine already has. The runtime remembers what has focus, which is why it knows what to reveal.
  - **A touch target is never smaller than the guidelines allow.** Forty-four points, counting a hit slop, on everything a finger lands on. `gui/tests/guidelines_test.lua` walks every screen of the gallery and fails naming what is too small, so this cannot rot.
  - **A declaration is a promise, and a test keeps it.** `support.host` says its props are the ones a renderer honours and `docs/components.md` is generated from them, so a prop listed there is one a caller writes and believes. `gui/tools/promises.lua` reads every declaration and searches the three renderers and the components for the prop by name, and `gui/tests/promises_test.lua` fails when nothing anywhere reads one. A sweep found two hundred and fifty-four. A prop that exists only in the documentation is worse than one that does not exist, so a new one is either honoured somewhere or it is not declared.
  - **A handle a component holds is named rather than built.** `self:ref("camera")` answers the same handle for the life of the component: one built in the render is a new handle on every commit pointing at nothing until the commit after, and one built in `onMount` does not exist for the first render at all, which is a screen whose first press reaches nothing. A definition may not carry a method named as one every component already answers — `ref`, `after`, `every`, `setState`, `visible` — since the engine would then call the caller's, which is a screen that draws nothing with nothing saying why.
  - **A source that names a scheme is somewhere else, not a name in the bundle.** Only `http` and `https` are fetched by the engine, since a phone hands one to its image view and quietly draws nothing. Everything else carrying a scheme — the `blob:` a page captures into, the `file:` a platform answers a chooser with — is already something the platform can open and is handed straight over. Matching a scheme only when two slashes followed it left every capture refused as a picture nobody bundled.
  - **A page outlives the engine drawing into it.** A wasm trap leaves the last frame on screen looking like a layout defect that no longer answers a finger, so the pump stops, says so, and marks the surface: what it drew is drained of its colour and takes no press. The phones need none of this, since an engine that dies there takes the process with it.
  - **A commit that fails does not take the application with it.** `Runtime:commit` runs the build under `pcall` and restores `committing` either way, then re-raises. A flag left set makes `needsCommit()` answer false forever, so one bad render, one refused batch or one missing asset would leave the application dead while still running.
  - **A failure reaches the host, not the log.** Opening a project runs on a coroutine, so a failure there would be reported where nobody is looking. `launch.start` takes an `onProblem`, every host registers `gui_problem`, and every sample app shows what it is told. A blank screen that says nothing is the defect this closes.
  - **What a handler does is not the runtime's to trust.** `Runtime:dispatch` runs a caller's handler under `pcall` and reports the failure through `onProblem`, since an error escaping into the host's event delivery takes the frame with it.
  - **An overlay is built rather than asked for.** `Modal`, `Sheet`, `Alert`, `ActionSheet`, `Menu`, `Toast`, `Accordion`, `TabBar`, `NavigationStack`, `Drawer`, `Table` and `RadioGroup` are Lua components that build a cover, a scrim and their content out of the host nodes that already exist, so they work on all three with nothing added to a renderer. A node type no renderer builds falls through to a plain box and puts nothing on screen, which is what "I press it and nothing happens" was.
  - **What is over the application is drawn through a portal.** An overlay laid out where it was written covers the box that surrounds it and nothing more, so a drawer raised from a screen inside a stack opened under the bar above it. `gui.Portal` is a node type rather than a component that moves a subtree around: what it holds stays where it was written for the state it reads, the context it is under and the commit that takes it down with its screen, while the engine lays it out as a tree of its own against the surface and each renderer hangs it from the surface rather than from the parent its insert names. `gui.over`, and so every overlay built on it, is drawn through one. Layers stack in the order they were inserted, which puts a portal written inside content that mounts later over one written earlier, and a layer takes no press of its own so an overlay with nothing shown in it lets a finger through to the screen it stands over.
  - **A theme is a look with an appearance on each side of it.** `gui.theme.define` builds one: everything written outside `light` and `dark` belongs to both, since a design is one thing and the two sides are two views of it. An application put in a look still follows the device — which side a reader is shown is theirs — where choosing one resolved theme pins it, and one resolved theme is a look with the same side twice rather than a case of its own. `gui.theme.builtin` is the framework's, a look like any other. Any screen changes it through `gui.theming`, which carries the name in use and the way to wear another and draws its readers again when it changes, so a settings screen needs no handle on the runtime.
  - **What the platform paints around the tree is the theme's.** A page, a window and an activity each draw a ground behind the surface, and a browser writes the captions of its own controls, a selection, a caret and a control's accent in colours of its own. None of that is a node, so the engine sends every renderer the look's ground — background, text, primary, the face and the appearance — through `showTheme`, and each paints its own. The page carries no colours at all: the reset, the surface and the ground are all in the renderer's stylesheet, read from what it was sent, so an application is what decides them rather than whatever html a host happens to ship.
  - **A look over a picture is one colour matrix, worked out once.** `gui.Image` takes a `filter` written as amounts — grey, sepia, inverted, hue, saturation, brightness, contrast — and the engine composes them, in that fixed order, into the one matrix a renderer applies. Sending seven names instead would be three platforms each interpreting them: the browser applies the matrix as a filter primitive told to work in the colours it was given rather than in linear light, iOS as a `CIColorMatrix` through a context told to manage no colour, and Android as a `ColorMatrixColorFilter` whose offsets count to 255 rather than to one. A filter that changes nothing is not sent at all. A tint replaces a picture's colours outright, so a picture carrying both is drawn in its tint, and what loads a picture, what tints it and what filters it are kept apart rather than written over each other in whatever order the props of a batch arrive.
  - **Everything shown over a screen reports both ends of both moves.** `onWillShow` and `onShow`, `onWillHide` and `onHide`, which is the model a platform tells a screen in and which the lifecycle already used. `onDismiss` is a request the reader made, not a moment, so the two live side by side: a caller told only that something was dismissed has to guess when it actually went, and guesses with a timer of its own written again in every screen. `gui.Presence` knows all four, so every overlay gets them by going through `gui.over`, and a toast goes through a portal like the rest rather than being drawn inside the screen that raised it.
  - **What a capture produced is kept by asking the platform.** A camera writes where the application may write, which nothing outside it can reach: the reader has nothing until it is somewhere they can open again. `gui.files.save` puts it where the platform keeps pictures and films — the photo library on a phone, a download in a browser — and `gui.files.share` hands it to the system's own sheet. Both answer a reply carrying where it ended up or a `problem` saying why it did not, since a reader who refused the library and a sheet they closed without choosing are ordinary rather than failures. Android writes through `MediaStore`, which is both what the gallery reads and what gives a file an address a chooser can send.
  - **A media element that will not play says so.** A browser refuses to start a sound a person did not ask for, and a file may be one nothing can open: both were answered to nobody, which is a play button that does nothing and a page that says nothing about why. `Audio` and `Video` carry `onError`, the rejected `play()` is caught on the page, and a failed item is observed on both phones.
  - **A style names a colour rather than the shorthand it could be written through.** The web renderer writes `backgroundColor`, since `background` clears the picture with it: a gradient painted its own run of colours and the style applied in the same batch wiped it out, on every gradient in the framework.
  - **A panel over the application keeps the system clear of what it holds.** Drawn through a portal it covers the whole surface, which puts it under the status bar and over the home indicator — a place a panel written inside a screen never reached. `gui.over` insets its content by the edges the panel actually touches, worked out from the panel's own placement, so the panel stays edge to edge and nothing in it is drawn under anything the system draws.
  - **A look reaches a picture, a film and a camera preview, and only a picture keeps it.** The same `filter` field is honoured by all three types on all three platforms: the browser draws each through a filter element, iOS through a `CIColorMatrix` — on a picture, on the video composition of a player item, and on the frames a capture session hands over — and Android through a colour filter, which is why its player draws into a `TextureView` rather than the surface a `VideoView` owns: a surface is composited past the view hierarchy and nothing the tree draws can colour it. A picture a camera takes carries the look into the file, since the frame is drawn again before it is written. A film keeps the pixels the hardware encoder wrote, so a look over one is drawn as it plays.
  - **A control reports the number the tree declared, not the position the platform tracks.** A slider maps its range and its step onto whatever the native control counts in and maps back when it reports, so the same Lua slider answers the same values on all three. Reading the position back as the value is how a slider reported a hundredth of what it was dragged to.
  - **A platform with no control for a type builds one out of parts of its own.** The engine sends `segmented`, `rating`, `stepper` and `picker` no children, so what is inside one belongs to the renderer the way a `UISegmentedControl`'s segments belong to UIKit. A type that draws as an empty box is not a renderer that is behind, it is a control nobody can use.
  - **A commit never names a node it removed in the same batch.** The index the style pass and the picture repaint walk is rebuilt inside the build, before either of them runs, and a component the dirty set still holds is skipped when an ancestor has already rendered it away. Both were remotely reachable ways to produce a batch that updates ids it had just removed, which kills the process on Android, throws out of the wasm callback on the web, and on iOS leaves the screen permanently half drawn with nothing said, since the diff only ever sends what changed and nothing repairs it.
  - **The layout answers what moved, and the runtime keeps every frame.** A caller that reveals a field or scrolls to a row asks about a node the layout had no reason to touch, so keeping only what moved left the map empty after the first state change and keyboard reveal did nothing at all.
  - **A build that fails keeps what it had not reached.** The dirty set is taken one node at a time rather than cleared up front, so a render that throws does not silently drop every component behind it — their state has already changed, and they would render stale until something unrelated marked them dirty again.
  - **A `setState` while a commit runs is recorded, not dropped.** A component notified by another one's render changes its state during the build, and returning early without recording it left the node dirty with nothing coming for it.
  - **A component whose root child changes type is put back where it was.** The replacement is attached to the nearest host above it, at the position the branch it stands in occupies. Reading a `parent` and an `index` that nothing ever assigned meant the old node was removed, the new one created, and nothing inserted: the ordinary spinner-then-content shape went permanently blank.
  - **Nothing the engine does inside a commit waits.** A commit holds the tree, so an `await` in the middle of one either raises outside a coroutine or yields with the tree halfway between two states, and every `setState` in that window is lost. A picture's bytes are asked for during the commit and answered after it, the way a fetch already was.
  - **A picture that could not be had is asked for once.** The answer to a failure schedules the repaint that asks again, so an unreachable image was one request and one full-tree commit per round, forever, and an application opened offline never stopped.
  - **The system's own bars are three settings, not one.** Which edges the tree keeps clear of, which bars the reader still sees, and what the marks in them are drawn in. Hiding one gives its room back, so the insets change with it and a screen stays correct across the change. What a platform cannot do it says through the `systemBars` capability: iOS takes the status bar away and will only let the home indicator fade, a browser has no bars and full screen instead and may only ask for it inside a gesture. What a reader does to bring a hidden bar back is always left alone.
  - **A failing test must be able to name itself.** A run piped through `grep … | tail -n` keeps the verdict and throws away the line that says which case failed, and a filter that never matches `error:` throws it away for everyone, every time. Both iOS steps of the workflow had the second shape. Keep the whole log when hunting a failure, and never reduce a test run to its summary.
  - **What the engine needs is not the screen's to declare.** A renderer binds an event when a handler for it crosses, so anything the engine itself listens for is reported only when the application happens to want it too. A field reports focus because the engine lifts it clear of the keyboard, and a surface reports its offset because the engine works out which boxes can be seen — neither because a screen asked. The suite's own keyboard case had been declaring the missing handler, which is why it never saw it.
  - **An application has three states and they mean three different things.** Active is in front and taking input, inactive is in front and not, background is out of sight and may be ended without another word. `gui.lifecycle` carries which, `gui_surface` answers the state at start so one launched out of sight is not told it is in front, and going from one way of being away to the other is not a return.
  - **What the engine owns stops while the application is away.** A suspended application runs nothing, a paused activity goes on running, and a hidden tab is throttled without stopping, so the same timer fires three ways. Anything from `self:after` or `self:every` waits and happens on the way back. A host emitting a lifecycle event pumps the engine in the same breath, since the frames stop when the window goes and a moment queued for a pump that is not coming is a screen never told it went away.
  - **Appearing is not being seen.** A stack keeps a screen mounted and shown while a box inside it is scrolled out of sight, so `onEnterView` and `onExitView` are the engine's arithmetic over the frames it laid out and the offsets it is told, cut by every surface between the box and the screen rather than measured against the screen alone. A surface is asked for its offset only while something under it is watching.
  - **A picture cut into nine is cut in its own pixels, so it is never resolved to a density variant.** `gui.NineSlice` points at a file with four numbers, and handing a renderer the `@2x` twice the size would cut it at those same four numbers and draw every corner at half the width it was authored at. `PIXELS` in the runtime is that third kind of source, beside the ones a density variant suits and the ones a platform player streams. A frame that has to be crisper is shipped larger and drawn smaller with `sliceScale`.
  - **A frame is painted over the box and never inside it.** Children arrive at frames the engine already worked out, so a border with a width of its own shifts every one of them inward by its own thickness — which is why the browser draws one with `border-image-width` over a border of nothing rather than with a real border. The same tree would otherwise be laid out one way in a browser and another way on a phone.
  - **A frame's padding clears the border the frame draws, which is the cut times the scale.** Anything less puts the content on top of the ornament, and how far it intrudes is then a property of whichever picture is in the frame rather than of the screen. It sat wrong from the first commit and nothing showed it, because the ornament was small enough to hide behind the text — heavier artwork put a bracket through the middle of a sentence.
  - **Artwork cut into nine is held to its cuts by reading the pixels.** Every row of a side edge has to be the same row and every column of a top or bottom edge the same column, or a shape crossing a cut line is drawn once in the corner and smeared in the strip beside it. Comparing stretched output with itself is the obvious check and does not see it. `tools/draw-frames.py` refuses to write a picture that fails, and the four numbers live in the screen and in that script, which `gui/tests/nineslice_test.lua` holds together — they had already drifted once.
  - **A prop a caller may write more than one way is written the one way before it goes anywhere.** A declaration's `normalise` runs before its `validate`, so the layout, the runtime and three renderers all read the same shape. `slice = 16` and `slice = { top = 16, … }` reach a renderer identically, since a shorthand each renderer reads for itself is three chances to read it differently.
  - **A natural minimum may depend on the props rather than on the type.** A frame cannot be narrower than the two corners it is cut at, and what those are is written on the node. `gui/layout/natural.lua` takes `minWidth` and `minHeight` as functions of the props the way it already took a size.
  - **Anything keyed by what an application produces is bounded.** Text measurements are keyed on the text itself, so a clock adds an entry a second for the life of the process, and a data URI is larger than the picture it carries. `gui/tools/cache.lua` holds a bounded number and gives up the coldest. A node id only ever increases, so an extent is dropped when its node is.
  - **A component asks for something later through `self:after`.** It checks the delay is a number of milliseconds, does nothing if the component has gone, and reports a failure rather than letting it out: a body handed to `spawn` is caught by nothing above it, so the engine reports it unhandled and stops the loop for that tick.
  - **An instance keeps the scheduler it was born under.** The component layer is pointed at one per runtime, and two runtimes in one process would otherwise share the last to start, so a component would ask a runtime that does not hold it to draw it.
  - **`Runtime:report` never raises.** It is reached from the middle of a commit and from the callbacks a commit owes, so raising there is the very failure it exists to contain. With no listener it writes to the log.
  - **A prop is honoured by all three or it is not declared**, and the check that keeps it only counts a name where a renderer could be reading it: not in a table keyed by node type, not in the factory that chooses a view for one, not in the type a component names itself after, and a bare table key only for an event. Each of those was giving a prop a pass against a row that had nothing to do with it.
  - **A colour on a control is the colour of the mark it draws**, which is a different thing from a style's colour, and all three took the platform's accent instead until it was built.
  - **An action asked of a node that cannot answer it is refused, the same way on all three.** `scrollTo` on something that does not scroll and `play` on something that is not a video each raise a named refusal, rather than one throwing, one doing nothing and one doing something else entirely.
  - **A picker reports what a calendar or a clock shows, never an instant.** `"2026-09-05"` and `"09:30"`, in and out. An instant carries a zone nobody chose, and reading it back in another one moves the day.
  - **The engine owns the icon set.** `gui/style/icons.lua` carries them as runs of points and `Icon` draws them onto a `canvas`, which every renderer already draws. A platform that ships thousands of symbols ships them under names no other platform has, so a name that resolved to one of those could only ever have drawn on one platform out of three.
  - **A string is measured with what it will be drawn with.** The spacing between its letters, the space between its lines and the slant of them all change how much room it needs, and a measurement is named by every one of them, or the same string at a different spacing answers the previous measurement.
  - **`setState({ x = nil })` clears nothing.** A Lua table has no key whose value is nil, so it is `setState({})` and the field keeps what it had. `gui.none` is what clears one. This cost an inbox its way back and left a camera showing a film after the next picture, so the suite reads every `setState` in the framework and the sample and fails on one that writes nil.
  - **A screen reads the route it was opened at, never the one the router is on now.** A stack holds the screen a pop is taking off for as long as the pop takes, so a shared provider renders it against the route it is leaving for. Each screen carries its own.
  - **A router tells a link from its own echo by what it drove, not by the address differing.** It sets the address itself while its own state change is still queued, so a push worked out from the difference puts the screen a pop just took off back on the trail, and the trail grows by one on every round trip.
  - **A look reaches a renderer four ways and a style is one of them.** The tint a control draws its own mark in, the run of colours a gradient is and the commands a canvas draws are props. Changing the look repaints all four, or every part of a screen the platform draws keeps the colours of the look before it.
  - **A renderer never queues one block on the main thread per frame.** A camera produces frames faster than a screen takes them, so one in flight at a time and the next is dropped. A backlog the main thread has to drain is what leaving a screen waits for.
  - **A surface showing the end of what it holds goes on showing it when its room shrinks**, which is the keyboard coming up on a conversation. A surface with nothing to scroll is not at its end — read as one, a list that fits is thrown to the bottom the moment it grows past its box.
  - **A device a platform demands a sentence for is declared before anything reaches for it.** iOS does not refuse an undeclared one, it ends the process: the photo library without `NSPhotoLibraryAddUsageDescription` takes the application down rather than being turned away. The suite reads what the demos reach for out of their own source.
  - **The photo library holds pictures and films.** A sound goes where the platform keeps a sound, which on iOS is the application's own documents with the bundle saying the Files application may see them.
  - **A name answered twice in one switch is a branch nothing reaches**, and the compiler says so where nobody reads it. A camera's zoom was read as a map's, and a sound, a film and a page were each left unable to report a failure at all.
  - **A setter on a renderer's own view that nothing in that renderer calls is a prop being dropped in silence.** No sound ever played on iOS because `setSource` was never called, and asking whether the name is read anywhere in the renderer does not see it, since the same word is read for a picture in the same file.
  - **A family is a name over several faces, and a renderer keeps every one of them.** The framework ships three weights of its own typeface, so a renderer that asks the system for the family by name, or keeps one face per family, draws bold text and plain text identically — which only ever shows by looking at a screen. Each keeps the faces by weight and draws the one nearest what a style asked for.
  - **The tree writing a value back is not a person choosing one.** A control set from a prop reports nothing, or a handler that stores what it was given comes round again as a second choice, and a platform that reports a programmatic change down two paths reports it twice. Each such control remembers what was written into it and reports only what was not.

  - **A command is an action, never a prop.** A prop carrying a moment is sent only when it differs from the last one, so a reader dragging a scrubber back to where they already were is answered by nothing at all, and clearing it when the drag ends removes the prop — which two renderers read as a seek to the beginning. Seeking, scrolling, focusing and taking a photograph are things a reader did once, and every one of them is asked through a ref. An action is declared beside the props it sits with, since a declaration is a promise either way, and `promises.unanswered()` holds each of them to being performed by all three renderers.
  - **A surface is asked where it is only while the engine has a use for the answer, and it answers the moment it is asked.** A scroll is reported by the pixel, so the question is put while something under it is watching to be seen or while there is a keyboard to lift a field clear of. Binding gives future reports and not the present value, so a surface reports once more when the handler lands — without that a reveal is worked out against an offset nobody has ever reported and a field is lifted from the wrong place.
  - **The keyboard is room taken away from a surface, and the engine gives it back.** A surface has nothing to scroll while its content fits, so a reveal that asked it to move anyway pushed the screen off the top of itself with no row below to come back from, and every field screen stayed there for the rest of the session. The engine adds the covered height to the surface's content extent, which is the inset every platform adds for one, lifts the field within it, and takes the room back when the keyboard goes — which is what brings the screen down. A surface is never asked to go further than its own content reaches, and one the layout has left scrolled past its content is brought back inside it.
  - **A bar is one thing that runs to the top of the glass, and a safe area says what is left of the insets.** Whether a bar adds the strip the status bar is drawn over cannot be worked out from a prop, since it depends on what stands above the bar rather than on what the bar was told. A safe area provides the insets it did not take to everything under it, so the same bar adds the strip on a screen drawn edge to edge and adds nothing inside a safe area. What the bar holds is centred in the part below the strip rather than in the whole of it, or the title sits under the clock.
  - **A large title belongs to the bar and so does the rule under it.** Drawn inside a screen it is a heading with the bar's own rule cut straight across the top of it, and it can never give way to the small title as the reader scrolls. The bar draws it, collapses it against how far the content has moved, and shows its rule at the moment the title gives way.
  - **A bar takes items rather than views.** Every platform offers one that way, and a bar built out of raw elements a screen at a time comes out at a different size, a different tint and a different touch target on every screen, half of them smaller than a finger. An item is a label, an icon, a picture, a badge or an element of the caller's, and the navigation stack's own way back is one of them rather than a special case.
  - **A screen arrives when it was not there the last time the stack drew.** The first screen a stack ever shows came from nowhere and there is nothing behind it for it to arrive over, so it is drawn where it is, which is what every platform does. Deciding it from whether the stack has drawn before instead is an `enter` appearing on the next unrelated commit for a screen that has not moved.
  - **An editor holds a document, and a field beside a preview is not one.** Nothing can be selected across a mark, the caret is never where the words are, and what is being written is drawn twice in two different shapes. The platform already holds a document as runs carrying marks — an attributed string, a spanned editable, a tree of elements — so the editor is the platform's own control and the marks cross as marks. A mark is semantic, so each platform draws its own bold and its own monospace rather than a weight the tree named, and only the colour a link takes comes from the look.
  - **A frame drawn from artwork carries artwork per state.** A frame is how a button is drawn from artwork and a button is a different picture while a finger is on it, so a caller names one per state and a state with none of its own draws the plain one. Each is resolved at the picture's own pixels for the same reason the single source is.
  - **A form is one thing, so it is written once.** Every screen that took input carried a state field per control, a string per mistake, a check before the button may be pressed and a rule somebody wrote again for an address or a length. The form holds the values, a field binds one control to one name, the rules everybody has ship with it, a caller's own function is a rule like any other, and a send that fails puts the keyboard in the first field on the screen that is wrong — first on the screen, which is why a field says where it is by joining the form as it draws.
  - **What is wrong with a form is worked out rather than kept.** Held in state it is a second copy of something the values already answer, and the two disagree for exactly as long as a commit takes: a form opens with every rule unchecked, so a button reading whether it may be sent is pressable for one frame on a form nobody has filled in.
  - **A key reaches whatever has focus, and it is named the way the browser names one.** That is what all three platforms deliver a key to, and `KeyboardEvent.key` is the only published set of names for keys — so iOS's HID usages and Android's key codes are mapped onto it rather than each reporting what its own platform calls a key. A box listening for one takes focus so that it can be reached.
  - **A method declared twice is a defect no language here reports.** A second declaration silently replaces the first: a method added for an editor took the name the whole browser renderer reported its events through, and every control on the page stopped reporting. The compiler says it for a switch on the two phones, and neither Lua nor a browser says anything, so `promises.redefined()` reads the browser renderer's classes and the runtime's own files.
  - **A prop answered twice in a run of checks is a dead branch unless a type tells the two apart.** The browser renderer routes props through `if (key === …)` rather than through a switch, so the first answer wins: an editor holds a document where a field holds a string, and the field's branch took both. `promises.shadowed()` answers those.
  - **What the engine holds about a node is let go of when the node is.** A node id only ever increases, so a store keyed by one grows for the life of the process: a screen opened and left a thousand times left a thousand offsets and a thousand extents behind, each about a surface that no longer exists. The invariant was already written down here and nothing kept it, which is the worst kind.
  - **A component that declares one of a pair of moments is never told the other.** `away and instance.onPause or instance.onResume` is the `and`/`or` shape again: with nothing to call for going away the `or` reached for the other one, and a screen that only wanted to be told it had come back was told so at the moment it went.
  - **A label a control answers to is worked out after the checks, never before them.** What a control says may be read out of the very props the checks refuse, so a value that was not a document at all reached the arithmetic that walks its runs and what the caller saw was an index into nothing.
  - **A test that drives a screen presses what a reader could press.** A stack keeps every screen it holds and draws the top one, so the rows underneath are in the tree and on nobody's screen: a case that reads their words passes for what a reader cannot see, and one that presses them presses through a screen. The harness skips anything under a box that takes no finger and anything under one drawn at no opacity.
  - **A picture that stands for something is drawn rather than downloaded.** A shop that pulls its pictures off a photograph service shows a bowl of strawberries under `Shell Chair` and a piano under `Trestle Table`. `tools/draw-products.py` and `tools/draw-covers.py` draw the artwork the sample is built out of, in one palette, so a grid of them reads as one catalogue.

- **`gui.X` is a component.** A family also carries the helpers its own components and its siblings are built from, so only what declares itself as a component reaches the public table. Anything else standing there is undocumented, untested, and enough to make a component named after it later fail as a name two families define.
- **Nothing in a demo is there to be looked at.** A control that answers a finger by doing nothing is a lie about what the framework does, and what the data behind it is does not matter. The suite fails on a handler with an empty body.
- **`x and y or z` is a bug wherever `y` can be nil.** Lua takes the `or` branch when the middle value is nil, so a layout that read `row and child.width or child.height` used a child's height as its width, one that read `row and child.height or child.width` centred a fixed column against its own width, and one that read `row and contentWidth or contentHeight` measured a chip inside a horizontal scroll against the height of a finger and clipped its label. Three of them, all real and all invisible to every test. Write the `if`. **Wherever `y` can only be a number it is correct and it stays**, since nought is true in Lua — rewriting those is churn that reads as a fix, and a sweep that widens the rule to every `and`/`or` in the tree is a sweep that changes nothing.
- **A look says what a control is coloured in, a control theme says what it is built out of, and the control theme reads the look.** They are two things the runtime holds and either may be changed without touching the other. A control theme names a colour **role** rather than a colour, which is what keeps them separate: the same design in two looks is two different-looking applications and one set of controls. Every role a drawn control may name exists in every look, since the ones a drawn control needs are worked out from the ones a look already carries — a look written before this library drew a control is still a complete palette.
- **A control is one public name and two ways of being drawn, and the control theme decides which.** `gui.Switch` is the platform's own switch under `native` and a drawn one under any other control theme, with nothing about the screen changed. A component that may be handed to the platform declares the host type as `platform`, so its props are held to being honoured by all three renderers exactly as a host node's own are, and the reference writes it as `` `switch` or Lua ``. `native` is the default, since a reader already knows how the control their own system draws behaves.
- **The control theme is read in one place.** The component that chooses reads it and hands it to the drawn one as a prop. Reading it in both marks both as owing a render when it changes, and the drawn one is then rendered against a theme that no longer draws it at all — which is an index into a table that says `platform` and nothing else.
- **A kind of control is registered, not listed, and it brings the entry it is drawn with.** A closed list of controls makes the control theme a menu rather than a platform: nobody can add an eleventh control or replace how one of the ten is drawn. `gui.controls.kind` declares a kind and its parts, `gui.control` declares a control that registers its own, and a control theme entry may carry `draw` — a component that replaces the drawing outright, since metrics and paint reshape a control and cannot rebuild one. A kind registered after a theme was written would otherwise leave that theme incomplete, including the four that ship, so a kind carries its own default and a theme writes over what it wants to change. The fallback is read at lookup rather than folded in at build, since the shipped themes are built the moment the library loads.
- **A control that no system draws names no platform node.** A round progress is one: what a system draws round is a spinner, which says something is happening rather than how much is done. Naming none is how a control says it is the engine's on every platform, and a theme that hands it to the platform is told so by name.
- **A drawn control answers a finger, a pointer and a keyboard.** A control that answers only a finger is half a control. Every drawn control is a stop on the way through with a keyboard, says when it has been reached, and answers the keys its own kind owns — space and return use a control, the arrows walk a set, and the arrows move a value in the opposite sense from the one they walk a set in, which is what every system does and what a reader expects of each. A pointer's second button and a finger held both raise `onContextPress` carrying where it happened. None of that is a renderer's business, so the behaviour is the same on all three rather than three platforms' worth of defaults.
- **A container of a set is not one of the set.** A segmented control, a navigation rail and a tab bar each hold the things a reader chooses between, and the container says it is nothing in particular while the members say what they are. A container that claims the members' role is announced as a control a reader can choose, and choosing it does nothing.
- **A drawn control costs what it looks like it costs, and the budget says so.** A screen of forty rows each holding a switch is 121 nodes under `native` and 221 under `material3`, and laying it out again takes 4.4 ms and 4.5 ms. Eighty per cent more nodes for two per cent more time, which is the engine doing the work rather than the bridge. `gui/tests/performance_test.lua` holds both the layout and the operations one press sends.
- **A focus ring is one thing for a whole design.** It is the same on every control a design draws, so it is carried once on the control theme rather than as a state on every part of every control, and it is a box outside the control rather than a border on it — a border changes what the layout gave the control, and a control that grew when the keyboard reached it would move the page.
- **A drawn control says what it is, what it is doing and what it is at.** A control the platform draws tells a screen reader all of that for itself. One the engine draws is a box with a colour in it, so a drawn checkbox that names no role is a checkbox nobody using VoiceOver or TalkBack can find, let alone tick. `accessibilityRole`, `accessibilityState` and `accessibilityValue` are universal props like `accessibilityLabel`, honoured by all three renderers, and every drawn control declares a role.
- **A drawn control is touched through a box at least the size of a finger.** A design publishes the size it draws a control at and every system publishes the smallest target a finger can reach, and they disagree: Material draws a 40dp button and asks for a 48dp target. The press is taken through the larger box and the smaller one is drawn inside it. A control the platform draws gets this for free, which is why a drawn set that forgets it is a regression rather than a difference.
- **A drawn control declares the size it has of its own.** A control the platform draws carries a natural size the layout reads off its declaration, and a drawn one is a box the layout knows nothing about: left to itself it fills the column it was written in, which is a switch as wide as the screen.
- **A key names one child, and two children under one key is refused where it is written.** The diff indexes the children it holds by key, so two of them under one key leave the second standing where the first was: both are drawn on the first commit, and on the commit after the first matches nothing, is taken down, and a row a screen drew disappears with no failure and no warning anywhere. The shape of a key was already checked — a table is refused by name — and the one thing a key is for was not. A key is only ever compared against its own siblings, so the same key under two different parents is two different children and stays allowed.
- **A name a file declares for itself and never reads is dead wherever it came from.** A local reaches nowhere but its own file, so an import left behind when a split moved the code away, or a constant a component now works out for itself, sits there for good: Lua says nothing, the suite says nothing, and a reader assumes it is used. `promises.unread()` answers every one of them.

## Lua style

- Match the existing visual, structural and architectural pattern. Compact, professional, consistent.
- Avoid excess vertical space. Use only the blank lines needed to separate reading contexts. **Separate blocks of different responsibility with one blank line.**
- Never leave multiple `if`s, validations, loops, state mutations and returns visually glued together. A function must read with an identifiable beginning, middle and end at a glance.
- Prefer early returns. Avoid unnecessary nesting. **No unnecessary `else` after a `return`.**
- Extract a function only when one is doing too much — never to shrink size or for artificial abstraction that hides the main flow.
- A module returns one table. Locals are declared at the top of the file, and a function that is not part of the module's surface is local.
- **No global writes.** Every module is `local M = {}` and `return M`.

## Comments

- **Most code has none.** The bar is that a reader who knows the language cannot work out the reason from the code in front of them.
- **Every comment is a complete sentence: it starts with a capital letter and ends with a full stop.**
- **A sentence never starts with a lowercase identifier.** Keep the identifier's exact spelling and reword the sentence so it is not the first word.
- **A comment above a function, method, class or module says what it does for the caller, never how it is implemented inside.**
- **Never break one sentence across lines, and never continue a sentence on the next line.** If you need a second sentence, close the first with a full stop and start the next on its own line.
- Comments are objective and natural. Nothing verbose, fragmented or narrative, no decorative banners, and no historical or before/after framing.
- A comment explains intent or context. It never restates what the code literally does, and usage examples belong in the docs.

- **A view is never placed by its frame on iOS.** `UIView.frame` is undefined while a view carries a transform, and the engine animates transforms while writing frames on every commit, so a commit landing inside an animation moved a view for good. Bounds and centre mean the same thing whatever the transform is — and only the size is written, since a scrolling view's `bounds.origin` is its content offset.

## Testing

- Every module has tests under `gui/tests/`, run by `python3 run.py test` against a released engine.
- **A renderer is proven by the conformance suite**, not by looking at a screen. All four run the same cases and apply operations identically, and `gui/tests/conformance_test.lua` refuses a suite that does not carry exactly the same case names.
- **A screen is proven by touching it.** `apps/ios/UITests` opens a demo from the index, types into a field, chooses a radio, counts a button, scrolls a list past the bar, opens a section, sorts a table and drives the request. Four of its twelve cases failed while every conformance case passed, because a tree-based case cannot see that a row will not answer a finger.
- **A screen is proven by looking at it.** A tree-based case cannot see a node that reached a renderer and was drawn as nothing, which is what an empty accordion, an invisible badge and a picture that never loaded each were. `python3 run.py shots` captures every screen in both appearances, on the simulator and in a browser.
- **The browser is a platform, so it is driven like one.** `renderers/web/tests/browser.test.js` opens the assembled page in a headless browser and holds what a document with no layout cannot: the size a control is drawn at, a caption standing beside its box rather than on it, where a pinned header sits at three offsets, and a window unfolded from 390 to 900 keeping what the reader had put into it. It walks the gallery the way a reader does, by pressing rows and scrolling to reach them, and it skips itself where the machine has no browser. `renderers/web/tools/` carries the protocol client the test and the screenshots both drive, with no dependency to install.
- The headless renderer records operations, so the framework is testable without a device.
- **A row that carries a name of its own is one element.** Its text is not exposed separately, so a UI case that asks for `staticTexts[...]` finds nothing and reads as a defect in the application. Ask for any element with that name.
- **A renderer's own defects are tested in the renderer's own language.** `renderers/ios/tests` runs under `xcodebuild`, `renderers/android/src/test` under Robolectric, `renderers/web/tests` under `node --test`. A defect that only exists inside `UILabel` or a `TouchDelegate` cannot be reached from Lua.
- **A test waits for the thing, never for the clock.** A fixed sleep is a race a busy machine wins: twenty milliseconds is plenty for a picture to be written on an idle laptop and not enough while the same machine is building an application for a phone, and a gate that fails where nothing is wrong is a gate nobody trusts. `gui/tests/waiting.lua` on the Lua side, `screen.settle()` and a bounded poll on the web, `waitForExistence` and an `NSPredicate` expectation in a UI case. The only sleep that is allowed is one where the sleep is the proof, because what is being shown is that nothing happens — a pulse on a tab nobody is looking at, a screen that has been taken down, a carousel told it may not loop — and those say so where they sleep. A bound on how long a tool waits is part of the same rule, and so is what a tool leaves behind: a browser is a tree of processes, closing one has to signal the whole group, and a suite that leaks seven of them per run eventually cannot start the next one — which it then reports as three defects in the renderer.
- **Asking an element that is gone whether it can be pressed raises rather than answering no.** A UI case that proves a screen was covered has to allow for the cover being total, since an element outside the snapshot has nothing to answer with. Ask whether it exists first, or wait on a predicate that reads `exists == NO OR ...`.
- **What a host is asked for includes what its own launch string calls.** Each renderer hands the engine a piece of Lua to start with and calls back into itself from inside it, so a function can be required of every host and appear nowhere under `gui/`. `gui/tests/host_test.lua` reads the three hosts as well as the framework, which is how `gui_framework` was found after `gui_problem` was added by hand.
- **A demo copies a shape and names nobody.** The applications in `sample/apps` are built after screens a reader already knows, and whose they are belongs to nobody here. `gui/tests/sample_test.lua` reads the sample and every page under `docs/` and fails on a product name in either. A word that is also ordinary English is deliberately not on that list.
- **A whole application is a test too.** `sample/apps/` carries eleven of them, each several screens with state, navigation and a keyboard, and `gui/tests/apps_test.lua` drives each down its main path. A component that works alone and falls apart in an application is one nobody would ship. The five built after products a reader already has are walked step by step — press this, then this is on screen and that is not, then this can be reached by a reader who cannot see it — and each ends by unwinding its whole stack and checking where it lands.
- **A list of children is spread last or not at all.** `table.unpack` in the middle of a table constructor yields one value rather than all of them, so a row written before a button is one row and a button: no nil, no error, and nothing on screen wrong enough to notice. It has cost four screens their contents. `promises.unspread()` fails on a spread that is not the last thing written in its element.
- **Every page in `docs/` is named by the README.** A page nothing links to is a page nobody reads, whatever is in it, and `gui/tests/components_test.lua` fails on an orphan.
- **A picture in the sample is drawn rather than fetched.** `tools/draw-products.py` and `tools/draw-scenes.py` draw every one of them from the shape of the thing it stands for, in the palette its own screen uses, so a shelf reads as one catalogue rather than as whatever a photograph service answered with. A map and a wallpaper are not files at all — each is a `gui.Canvas` worked out from the box it turned out to fill.

## Proving it

- **Touch it.** `apps/ios/UITests` opens every overlay by pressing what opens it. A screenshot shows the state a screen opens in, and a modal, a sheet, an alert, an action sheet, a toast, a menu and a drawer are none of them in it.
- **Look at it.** Every defect in section G of `docs/review.md` passed every suite here and was found by a person holding the application. `python3 run.py shots` and a real device see a class of defect no tree-based case can.
- **A test against a stand-in proves the stand-in.** A fake canvas has no size to be wrong about, so a canvas sized from the element's own box passed every web test and would have drawn nothing in a browser. Where a test cannot see the platform's own behaviour, say so rather than counting it as covered.
- **A stand-in models what the renderer leans on.** The renderer listens on the box around a control and reads what the control inside it raised, which is bubbling, and the stand-in document delivered an event to one element and stopped — so the only way a test could reach those handlers was by dispatching where the page never does. A stand-in that is missing the one behaviour the code depends on is a suite agreeing with itself.
- **A defect found on one platform is looked for on the other two before it is called closed.** The line count a frame overwrote, the radio that reported nothing, the surface that would not page: each was found on one renderer, fixed there, and left standing on another until a second read.
- **A fix is proven by a test that fails without it.** Write the test, revert the fix, watch it fail, put the fix back. Several of the worst findings of the last review were things a passing suite had been asserting the wrong way round, and three tests written this way each found a second defect the review had not seen.

## Docs

- **Prose in Markdown is never hard-wrapped.** One paragraph is one line, however long it runs, and a list item is one line with its continuation folded in.
- **A sentence starts with a capital letter.** The product is `Varn GUI` in prose. A sentence never opens with a lowercase identifier — reword it so the identifier is not first.
- `LICENSE.md` is never reformatted.
- Docs are two-tier. Tier one is the `README.md` next to the code. Tier two is the reference under `docs/`, which carries the complete API and a runnable example of every capability. `docs/components.md` is generated — regenerate it with `gui/tools/reference.lua` rather than editing its table by hand.
- `docs/roadmap.md` says what is covered and what is genuinely still open, and an item closes by moving into `docs/review.md` in the same change. A roadmap that lists shipped work as missing is worse than no roadmap.
- `docs/review.md` is the one live list, and an item closes only when it is built, tested and documented. Closing one means moving its box in the same change. A finished round's checklist is deleted rather than kept: four of them were kept once, they contradicted each other and the source, and one was linked from the `README` as documentation.
